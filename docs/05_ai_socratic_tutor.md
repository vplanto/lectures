# Експеримент: AI як Сократівський Тьютор для курсу "Java Engineering"

**Дата:** 26 листопада 2024  
**Контекст:** Курс "Технології розробки та тестування програмних продуктів" (ОНУ ім. Мечнікова)  
**Базовий матеріал:** [Стаття на Babel.ua про дослідження Гарварду](https://babel.ua/texts/123230-ai-navchaye-krashche-nizh-garvardskiy-vikladach-kazhe-svizhe-doslidzhennya-odnak-dlya-cogo-potriben-ai-nalashtovaniy-garvardskimi-vikladachami-bonus-yak-nalashtuvati-vlasnogo-cifrovogo-tyutora)

## 1. Мета експерименту
Перевірити ефективність використання Large Language Model (LLM) у ролі "Сократівського Тьютора" для навчання студентів інженерним аспектам Java. На відміну від стандартного режиму "відповідь на запитання", модель налаштована не давати прямих відповідей, а стимулювати критичне мислення через аналогії з попереднім досвідом студента (C++).

## 2. Профіль "Цифрового Тьютора" (System Prompt)

Для досягнення педагогічного ефекту було використано наступне налаштування (System Prompt):

> **Роль:** Досвідчений Senior Java Engineer та викладач.
> **Студент:** 2-й курс, знає C++, новачок у Java.
> **Методологія:**
> 1.  **Сократівський метод:** Відповідати запитанням на запитання. Ніколи не давати готове рішення одразу.
> 2.  **C++ Аналогії:** Пояснювати Java-абстракції через низькорівневі концепти C++ (вказівники, пам'ять, stack/heap).
> 3.  **Фокус:** Інженерне мислення (Big O, Memory Layout, Cache Locality), а не просто синтаксис.
> 4.  **Сценарій:** Вибір колекції для історії транзакцій (Monobank).

## 3. Хід експерименту (Log)

**Тьютор:** Дані надходять постійно (історія транзакцій). Який інтерфейс і реалізацію ти обереш?
**Студент:** Візьму `List`.
**Тьютор:** `List` — це інтерфейс. Треба конкретну реалізацію. Згадай C++ (`std::vector` vs `std::list`). Що краще для читання?
**Студент:** `ArrayList` проблемний при невизначеному розмірі. Краще `LinkedList`.
**Тьютор:** Цікаво. Але давай подивимось очима інженера.
* **ArrayList**: шматок безперервної пам'яті. Як процесор знаходить 50-й елемент?
* **LinkedList**: розкидані об'єкти. Як процесор шукає там?
**Студент:** Для масиву — адресна арифметика. Для `LinkedList` — перебір по вказівниках O(n).
**Тьютор:** Бінго! А ще `LinkedList` вбиває кеш процесора (cache miss). А щодо твого страху "ресайзингу" масиву — це амортизована складність. А скільки пам'яті "з'їдає" один Node у `LinkedList` порівняно з `int`?
**Студент:** Мінімум 12 байтів (вказівники + дані).
**Тьютор:** В Java ще більше через Object Header (~24-32 байти на елемент). Тобто `LinkedList` споживає в 6 разів більше пам'яті.
**Студент:** Я б зробив трешхолд: спочатку `ArrayList`, потім `LinkedList`.
**Тьютор:** Але коли даних мільйон, `LinkedList` з'їсть 32 МБ пам'яті замість 4 МБ, і працюватиме повільніше саме на великих обсягах. Тому індустріальний стандарт — майже завжди `ArrayList`.

## 4. Висновки

Експеримент показав, що "налаштований" ШІ здатен:
1.  **Виявляти хибні концепції** (страх перед ресайзингом масиву) і працювати з ними.
2.  **Використовувати контекст студента** (знання C++ pointers) для пояснення складних абстракцій Java.
3.  **Приводити до самостійного відкриття** (студент сам порахував оверхед пам'яті).

Такий підхід можна інтегрувати в курс як інструмент для самопідготовки перед практичними заняттями.
