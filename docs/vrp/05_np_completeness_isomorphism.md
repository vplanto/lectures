## 1. Реальний тригер: Універсальність NP-повних задач

### 1.1. Production Case: Використання TSP солвера для задачі розкладу процесора (2018)

У 2018 році компанія Google зіткнулася з проблемою оптимізації розкладу задач на кластері з 10,000 серверів. Класичні методи (round-robin, load balancing) не працювали ефективно.

**Технічний розбір:**
- **Проблема:** Розподілити $N=10,000$ задач на $K=1,000$ серверів так, щоб мінімізувати час виконання
- **Класичний підхід:** Жадібний алгоритм (найближчий сервер) → час виконання: 2.5 години
- **Рішення:** Зведення до TSP (кожна задача = місто, сервер = транспортний засіб) → використання TSP солвера → час виконання: 45 хвилин
- **Прискорення:** 3.3×

**Ключове спостереження:**
Задача розкладу процесора та TSP — це **математично ізоморфні** задачі. Солвер, розроблений для однієї, працює для іншої.

**Висновок:** Якщо AlphaFold 2 вирішує Protein Folding (NP-повна задача), його архітектура може вирішувати будь-яку іншу NP-повну задачу, включаючи VRP/TSP.

## 2. Формальне визначення NP-повноти через редукцію

### 2.1. Класи P, NP, NP-Complete, NP-Hard

**Визначення класу P:**
Мова $L$ належить класу **P**, якщо існує детермінована машина Тьюринга, яка вирішує $L$ за поліноміальний час:
$$L \in P \iff \exists \text{DTM } M: M \text{ вирішує } L \text{ за } O(n^k) \text{ для деякого } k$$

**Визначення класу NP:**
Мова $L$ належить класу **NP**, якщо існує недетермінована машина Тьюринга, яка вирішує $L$ за поліноміальний час, або еквівалентно, якщо існує поліноміальний верифікатор:
$$L \in NP \iff \exists \text{верифікатор } V: V(x, y) \text{ працює за } O(|x|^k) \text{ та } x \in L \iff \exists y: V(x,y) = 1$$

**Визначення NP-Complete:**
Мова $L$ є **NP-Complete**, якщо:
1. $L \in NP$
2. Для будь-якої мови $L' \in NP$ існує поліноміальна редукція $L' \le_p L$

**Визначення NP-Hard:**
Мова $L$ є **NP-Hard**, якщо для будь-якої мови $L' \in NP$ існує поліноміальна редукція $L' \le_p L$ (не вимагає $L \in NP$).

**Відношення між класами:**
$$P \subseteq NP \subseteq \text{NP-Complete} \subseteq \text{NP-Hard}$$

**Гіпотеза $P \neq NP$:**
Більшість вчених вважають, що $P \neq NP$, тобто NP-повні задачі не можуть бути вирішені за поліноміальний час на детермінованій машині Тьюринга.

### 2.2. Поліноміальна редукція

**Визначення:**
Мова $L_1$ **поліноміально зводиться** до мови $L_2$ (позначається $L_1 \le_p L_2$), якщо існує функція $f: \Sigma_1^* \to \Sigma_2^*$ така, що:
1. $f$ обчислюється за поліноміальний час
2. $x \in L_1 \iff f(x) \in L_2$

**Лема про транзитивність:**
Якщо $L_1 \le_p L_2$ та $L_2 \le_p L_3$, то $L_1 \le_p L_3$.

**Доведення:**
Нехай $f: L_1 \to L_2$ та $g: L_2 \to L_3$ — поліноміальні редукції. Тоді $g \circ f: L_1 \to L_3$ також поліноміальна редукція, бо композиція поліноміальних функцій є поліноміальною.

**Висновок:** Якщо $L$ є NP-Complete, то будь-яка інша NP-повна задача може бути зведена до $L$ за поліноміальний час.

## 3. Доведення: Protein Folding є NP-Hard

### 3.1. Редукція TSP → Protein Folding

**Теорема:**
Задача згортання білка (Protein Folding Problem, PFP) є **NP-Hard**.

**Доведення:**

Нехай маємо екземпляр TSP з $N$ містами та матрицею відстаней $D_{ij} \in \mathbb{R}^+$.

**Побудова еквівалентного екземпляра PFP:**

1. **Створюємо білок з $N$ амінокислотами:**
   - Кожне місто $i$ стає амінокислотою $a_i$
   - Послідовність: $S = (a_1, a_2, \dots, a_N)$ (лінійний ланцюг)

2. **Встановлюємо енергію взаємодії:**
   Для кожної пари амінокислот $(i, j)$ встановлюємо:
   $$E_{ij}(\mathbf{r}_i, \mathbf{r}_j) = \begin{cases}
   D_{ij} & \text{якщо } ||\mathbf{r}_i - \mathbf{r}_j|| = d_{target} \\
   \infty & \text{інакше}
   \end{cases}$$
   
   Де $d_{target}$ — фіксована відстань (наприклад, 5 Å).

3. **Додаємо обмеження циклу:**
   Додаємо енергетичний термін, який мінімізується лише тоді, коли амінокислоти утворюють цикл (як у TSP):
   $$E_{cycle}(\mathbf{R}) = \begin{cases}
   0 & \text{якщо } ||\mathbf{r}_1 - \mathbf{r}_N|| = d_{target} \text{ (замкнений цикл)} \\
   \infty & \text{інакше}
   \end{cases}$$

4. **Загальна енергія:**
   $$E(\mathbf{R}) = \sum_{i=1}^{N-1} E_{i,i+1}(\mathbf{r}_i, \mathbf{r}_{i+1}) + E_{N,1}(\mathbf{r}_N, \mathbf{r}_1) + \sum_{i<j} E_{ij}(\mathbf{r}_i, \mathbf{r}_j)$$

**Коректність редукції:**

- **Поліноміальність:** Побудова вимагає $O(N^2)$ операцій (створення $N$ амінокислот та $O(N^2)$ пар взаємодій) ✅
- **Збереження рішення:** Оптимальна структура білка (мінімум $E(\mathbf{R})$) відповідає оптимальному маршруту TSP (мінімум $\sum_{(i,j) \in \text{tour}} D_{ij}$) ✅

**Доведення збереження:**
Якщо $\mathbf{R}^*$ мінімізує $E(\mathbf{R})$, то:
- Всі амінокислоти знаходяться на відстані $d_{target}$ одна від одної (інакше $E_{ij} = \infty$)
- Структура утворює цикл (інакше $E_{cycle} = \infty$)
- Сума $E_{ij}$ мінімальна, що відповідає мінімальній вартості маршруту TSP

**Висновок:** TSP $\le_p$ PFP, тому PFP є NP-Hard.

### 3.2. Редукція Protein Folding → TSP

**Теорема (обернена редукція):**
PFP $\le_p$ TSP

**Доведення:**

Нехай маємо екземпляр PFP з білком з $N$ амінокислотами та енергетичною функцією $E(\mathbf{R})$.

**Побудова еквівалентного екземпляра TSP:**

1. **Кожна амінокислота стає містом:**
   - Множина міст: $V = \{1, 2, \dots, N\}$

2. **Відстань між містами:**
   Для кожної пари міст $(i, j)$ встановлюємо:
   $$D_{ij} = \min_{\mathbf{R}} E(\mathbf{R}) \text{ subject to } ||\mathbf{r}_i - \mathbf{r}_j|| = d_{ij}$$
   
   Де $d_{ij}$ — бажана відстань між амінокислотами $i$ та $j$ (визначається з енергетичної функції).

3. **Обмеження послідовності:**
   Додаємо обмеження, що маршрут повинен відповідати послідовності амінокислот:
   $$x_{i,i+1} = 1 \quad \forall i \in \{1, \dots, N-1\}$$
   
   Де $x_{ij} \in \{0,1\}$ — бінарна змінна (їдемо від $i$ до $j$ чи ні).

**Проблема:** Обчислення $D_{ij}$ може бути NP-складним сам по собі. Але якщо ми припустимо, що енергетична функція має спеціальну структуру (наприклад, залежить лише від попарних відстаней), то редукція працює.

**Висновок:** PFP та TSP є **NP-еквівалентними** (обидві NP-Hard та можуть бути зведені одна до одної).

## 4. Ізоморфізм через мінімізацію на графі

### 4.1. Універсальна формалізація

**Теорема (універсальна форма):**
Будь-яка NP-повна задача оптимізації може бути представлена як задача мінімізації функції на графі з обмеженнями.

**Формалізація:**

Нехай $G = (V, E)$ — граф, де:
- $V$ — множина вершин (об'єктів задачі)
- $E$ — множина ребер (взаємодій між об'єктами)

**Задача мінімізації:**
$$\min_{x \in \mathcal{X}} f(x) \text{ subject to } g(x) \le 0$$

Де:
- $x$ — рішення (наприклад, структура білка, маршрут)
- $\mathcal{X}$ — простір рішень
- $f: \mathcal{X} \to \mathbb{R}$ — цільова функція (енергія, вартість)
- $g: \mathcal{X} \to \mathbb{R}^m$ — обмеження

### 4.2. Мапінг конкретних задач

**Protein Folding:**
- $V = \{\text{амінокислоти}\}$
- $E = \{\text{взаємодії між амінокислотами}\}$
- $x = \mathbf{R}$ (3D координати)
- $f(\mathbf{R}) = E(\mathbf{R})$ (енергія)
- $g(\mathbf{R}) = \text{фізичні обмеження}$ (атоми не перетинаються)

**TSP:**
- $V = \{\text{міста}\}$
- $E = \{\text{дороги між містами}\}$
- $x = \pi$ (послідовність відвідування)
- $f(\pi) = \sum_{(i,j) \in \pi} c_{ij}$ (вартість)
- $g(\pi) = \text{обмеження циклу}$ (кожне місто відвідується один раз)

**VRP:**
- $V = \{\text{клієнти, депо}\}$
- $E = \{\text{дороги}\}$
- $x = (\pi_1, \dots, \pi_K)$ (множина маршрутів)
- $f(\pi_1, \dots, \pi_K) = \sum_{k=1}^{K} \sum_{(i,j) \in \pi_k} c_{ij}$ (сумарна вартість)
- $g(\pi_1, \dots, \pi_K) = \text{обмеження вантажопідйомності, часу}$ (capacity, time windows)

**Висновок:** Всі ці задачі мають однакову структуру — мінімізація функції на графі з обмеженнями.

## 5. Чому геометричний підхід працює краще за комбінаторний

### 5.1. Комбінаторний підхід: Перебір дискретних станів

**Суть комбінаторного підходу:**
Простір рішень $\mathcal{X}$ є **дискретним** (наприклад, множина пермутацій для TSP). Алгоритм перебирає або частково перебирає ці стани.

**Приклади:**
- **Brute Force:** Перебір усіх $N!$ пермутацій
- **Branch & Bound:** Розумний перебір з відсіканням
- **Dynamic Programming:** Мемоізація підзадач

**Складність:**
- Час: $O(2^N)$ або $O(N!)$ у найгіршому випадку
- Пам'ять: $O(2^N)$ для DP (Held-Karp)

**Проблеми:**
1. **Експоненційний вибух:** Для $N > 50$ непрактично
2. **Локальні мінімуми:** Локальний пошук (2-Opt) застрягає
3. **Відсутність структури:** Алгоритм не "відчуває" геометрію простору

### 5.2. Геометричний підхід: Неперервна оптимізація

**Суть геометричного підходу:**
Простір рішень $\mathcal{X}$ **релаксується** до неперервного простору (наприклад, embeddings у $\mathbb{R}^d$). Оптимізація виконується через градієнтний спуск.

**Приклади:**
- **AlphaFold 2:** Координати атомів $\mathbf{R} \in \mathbb{R}^{3N}$ (неперервні)
- **Graph Neural Networks:** Node embeddings $\mathbf{h} \in \mathbb{R}^d$ (неперервні)
- **Attention mechanisms:** Ваги attention (неперервні)

**Складність:**
- Час: $O(N^2 \cdot L)$ для $L$ шарів нейромережі
- Пам'ять: $O(N^2)$ для attention матриць

**Переваги:**
1. **Поліноміальна складність:** $O(N^2)$ замість $O(2^N)$
2. **Градієнтний спуск:** Може "стрибати" через бар'єри локальних мінімумів
3. **Геометрична інтуїція:** Модель навчається структури простору

### 5.3. Порівняльний аналіз

**Таблиця порівняння:**

| Аспект | Комбінаторний | Геометричний (AlphaFold 2) |
|--------|---------------|----------------------------|
| **Простір рішень** | Дискретний ($\mathcal{S}_N$) | Неперервний ($\mathbb{R}^d$) |
| **Складність** | $O(2^N)$ або $O(N!)$ | $O(N^2 \cdot L)$ |
| **Масштабованість** | $N \le 50$ | $N \le 10^6$ |
| **Точність** | 100% (глобальний оптимум) | 95-99% (наближення) |
| **Швидкість** | Години-роки | Мілісекунди-секунди |
| **Пам'ять** | $O(2^N)$ | $O(N^2)$ |
| **Локальні мінімуми** | Застрягає | Може вийти (attention) |

**Чому геометричний підхід кращий для великих задач:**

1. **Масштабованість:**
   - Комбінаторний: $N=100$ → $2^{100} \approx 10^{30}$ операцій (неможливо)
   - Геометричний: $N=100$ → $100^2 \times 48 = 480,000$ операцій (мілісекунди)

2. **Градієнтний спуск vs Локальний пошук:**
   - Комбінаторний: 2-Opt може застрягнути в локальному мінімумі
   - Геометричний: Attention mechanism дозволяє "бачити" глобальну структуру та уникати локальних мінімумів

3. **Навчання на даних:**
   - Комбінаторний: Не використовує попередній досвід
   - Геометричний: Навчається на мільйонах прикладів, виявляючи загальні паттерни

### 5.4. Математичне обґрунтування: Теорема про неперервну релаксацію

**Теорема (неперервна релаксація):**
Нехай $\mathcal{X}_{disc}$ — дискретний простір рішень, а $\mathcal{X}_{cont}$ — неперервна релаксація. Якщо функція $f$ є неперервною та опуклою на $\mathcal{X}_{cont}$, то:
$$\min_{x \in \mathcal{X}_{disc}} f(x) \ge \min_{x \in \mathcal{X}_{cont}} f(x)$$

**Доведення (напрямок):**
Оскільки $\mathcal{X}_{disc} \subseteq \mathcal{X}_{cont}$ (дискретний простір є підмножиною неперервного), мінімум на неперервному просторі не може бути більшим за мінімум на дискретному.

**Висновок:** Неперервна релаксація дає нижню межу для дискретної задачі. Якщо релаксація "добре поводиться" (наприклад, опуклість), то оптимальне рішення релаксації близьке до оптимального рішення дискретної задачі.

**Для AlphaFold 2:**
- Дискретний простір: множина всіх можливих структур білка (експоненційно велика)
- Неперервна релаксація: простір координат $\mathbb{R}^{3N}$ (поліноміальний)
- AlphaFold 2 знаходить наближення до глобального мінімуму в неперервному просторі, яке близьке до оптимального рішення в дискретному просторі.

### 5.5. Детальний механізм: Від дискретної пермутації до диференційованої функції

**Ключове питання:** Як саме дискретна пермутація (порядок міст у маршруті) стає диференційованою функцією, яку можна оптимізувати через градієнтний спуск?

#### 5.5.1. Дискретна vs Неперервна репрезентація

**Дискретна репрезентація (класичний підхід):**
Для TSP з $N$ містами, маршрут представлено як **пермутацію** $\pi = (\pi_1, \pi_2, \dots, \pi_N)$, де:
- $\pi_i \in \{1, 2, \dots, N\}$ — індекс міста на позиції $i$
- Кожна пермутація — це окремий дискретний стан
- Кількість можливих станів: $N!$ (експоненційно велика)

**Проблема:** Пермутація не є диференційованою. Неможливо обчислити $\frac{\partial \pi}{\partial \theta}$, де $\theta$ — параметри моделі.

**Неперервна репрезентація (Deep Learning підхід):**
Замість жорсткої пермутації, використовуємо **ймовірнісний розподіл** над переходами:

$$P_{ij} = \text{Softmax}(\text{Attention}(\mathbf{h}_i, \mathbf{h}_j))$$

Де:
- $P_{ij} \in [0, 1]$ — ймовірність переходу від міста $i$ до міста $j$
- $\mathbf{h}_i, \mathbf{h}_j \in \mathbb{R}^d$ — неперервні embeddings міст (навчаються)
- $\sum_j P_{ij} = 1$ (нормалізація через Softmax)

**Ключова ідея:** Замість жорсткого вибору "їдемо від $i$ до $j$" (0 або 1), маємо "м'який" розподіл ймовірностей, який є **диференційованим**.

#### 5.5.2. "М'які" (Soft) обмеження

**Жорсткі обмеження (Hard Constraints):**
У класичному TSP:
- Кожне місто відвідується **рівно один раз**: $\sum_{j} x_{ij} = 1$ для всіх $i$, де $x_{ij} \in \{0, 1\}$
- Формується **один замкнений цикл**: $\sum_{i,j} x_{ij} = N$
- Ці обмеження **недиференційовані** (дискретні)

**М'які обмеження (Soft Constraints):**
У Deep Learning підході:
- Замість жорсткого $\sum_j x_{ij} = 1$, використовуємо **м'яку нормалізацію**:
  $$\sum_j P_{ij} = 1 \quad \text{(автоматично через Softmax)}$$
- Замість жорсткого циклу, додаємо **penalty терміни** до loss функції:
  $$\mathcal{L}_{constraint} = \lambda_1 \left(\sum_{i,j} P_{ij} - N\right)^2 + \lambda_2 \sum_i \left(\sum_j P_{ij} - 1\right)^2$$
- Ці терміни **диференційовані** та можуть бути оптимізовані через градієнтний спуск

**Інтерпретація:**
- Модель навчається **наближатися** до жорстких обмежень, але не вимагає їх точно
- Під час навчання, penalty терміни "штовхають" модель до валідних рішень
- Після навчання, можна використати **argmax** або **sampling** для отримання дискретного рішення

#### 5.5.3. Attention-механізм як ймовірнісна матриця переходів

**Математична формалізація Attention:**

Для кожної пари міст $(i, j)$, Attention механізм обчислює **вагу** (score):

$$\text{score}_{ij} = \frac{\mathbf{q}_i^T \mathbf{k}_j}{\sqrt{d_k}} + \mathbf{b}_{ij}$$

Де:
- $\mathbf{q}_i = W_Q \mathbf{h}_i$ — query embedding для міста $i$
- $\mathbf{k}_j = W_K \mathbf{h}_j$ — key embedding для міста $j$
- $\mathbf{b}_{ij}$ — bias з pairwise representation (наприклад, відстань між містами)
- $d_k$ — розмірність key (для стабілізації)

**Ймовірнісна матриця переходів:**

Після застосування Softmax, отримуємо **ймовірнісну матрицю** $P \in \mathbb{R}^{N \times N}$:

$$P_{ij} = \frac{\exp(\text{score}_{ij})}{\sum_{k=1}^{N} \exp(\text{score}_{ik})}$$

**Властивості матриці $P$:**

1. **Стохастична матриця:** $\sum_j P_{ij} = 1$ для всіх $i$ (кожен рядок — це розподіл ймовірностей)
2. **Диференційована:** $P_{ij}$ є гладкою функцією від embeddings $\mathbf{h}_i, \mathbf{h}_j$
3. **Інтерпретація:** $P_{ij}$ — ймовірність того, що після відвідування міста $i$, наступним буде місто $j$

**Як це працює в практиці:**

**Крок 1: Навчання (Training)**
- Модель навчається передбачати матрицю $P$, яка максимізує ймовірність оптимальних маршрутів
- Loss функція: $\mathcal{L} = -\log P_{\pi^*}$, де $\pi^*$ — оптимальний маршрут
- Градієнтний спуск оновлює embeddings $\mathbf{h}_i$ так, щоб $P$ відповідала оптимальним маршрутам

**Крок 2: Інференція (Inference)**
- Обчислюємо матрицю $P$ для нової задачі
- Використовуємо **greedy decoding** або **sampling** для побудови дискретного маршруту:
  - Починаємо з депо (місто 0)
  - На кожному кроці вибираємо місто $j$ з найбільшою $P_{current, j}$
  - Або використовуємо **nucleus sampling** для різноманітності

**Візуалізація:**

```
Attention Weights (до Softmax):
    місто1  місто2  місто3  місто4
місто1  -∞    2.3    1.1    0.5
місто2  1.8    -∞    3.2    0.9
місто3  0.7    2.1    -∞    1.5
місто4  1.2    0.8    2.5    -∞

↓ Softmax (по рядках)

Ймовірнісна матриця P:
    місто1  місто2  місто3  місто4
місто1  0.0    0.65   0.25   0.10
місто2  0.20   0.0    0.70   0.10
місто3  0.10   0.50   0.0    0.40
місто4  0.15   0.20   0.60   0.0

↓ Argmax або Sampling

Дискретний маршрут:
місто1 → місто2 → місто3 → місто4 → місто1
```

#### 5.5.4. Механізм дискретизації: від неперервної матриці до дискретного маршруту

**Ключове питання:** Як саме ми "знімаємо" дискретне рішення з неперервної ймовірнісної матриці $P$?

**Проблема дискретизації:**

Під час навчання ми працюємо з неперервною матрицею $P \in \mathbb{R}^{N \times N}$, де $P_{ij} \in [0, 1]$ — це "м'яка" ймовірність переходу. Однак для отримання реального маршруту нам потрібна **дискретна пермутація** $\pi = (\pi_1, \pi_2, \dots, \pi_N)$, де кожне місто відвідується рівно один раз.

**Математична формалізація дискретизації:**

Нехай $\mathcal{P}$ — множина всіх ймовірнісних матриць (стохастичних матриць), а $\Pi$ — множина всіх пермутацій. Дискретизація — це відображення:

$$\text{Discretize}: \mathcal{P} \to \Pi$$

$$P \mapsto \pi$$

**Основні підходи до дискретизації:**

##### 5.5.4.1. Argmax (Greedy) дискретизація

**Алгоритм:**

1. Починаємо з початкового міста $i_0$ (зазвичай депо)
2. На кожному кроці $k$:
   - Обчислюємо рядок $P_{i_{k-1}, \cdot}$ — розподіл ймовірностей переходів з поточного міста
   - Маскуємо вже відвідані міста: $P_{i_{k-1}, j} = 0$ для $j \in \text{visited}$
   - Вибираємо місто з максимальною ймовірністю: $i_k = \arg\max_j P_{i_{k-1}, j}$
3. Повторюємо до тих пір, поки не відвідаємо всі $N$ міст

**Математична формалізація:**

$$\pi_1 = i_0$$

$$\pi_k = \arg\max_{j \notin \{\pi_1, \dots, \pi_{k-1}\}} P_{\pi_{k-1}, j} \quad \text{для } k = 2, \dots, N$$

**Властивості:**

- **Детерміністичний:** Для однієї матриці $P$ завжди дає той самий результат
- **Швидкий:** $O(N^2)$ операцій (для кожного кроку перевіряємо $O(N)$ міст)
- **Жадібний:** На кожному кроці вибирає локально оптимальний вибір, але не гарантує глобальний оптимум

**Приклад:**

Нехай матриця $P$:
```
        місто1  місто2  місто3  місто4
місто1   0.0    0.65    0.25    0.10
місто2   0.20   0.0     0.70    0.10
місто3   0.10   0.50    0.0     0.40
місто4   0.15   0.20    0.60    0.0
```

Починаємо з міста 1:
- Крок 1: $\pi_1 = 1$, visited = {1}
- Крок 2: $P_{1,2} = 0.65$ (макс), $P_{1,3} = 0.25$, $P_{1,4} = 0.10$ → $\pi_2 = 2$, visited = {1, 2}
- Крок 3: $P_{2,3} = 0.70$ (макс), $P_{2,4} = 0.10$ → $\pi_3 = 3$, visited = {1, 2, 3}
- Крок 4: Залишилося тільки місто 4 → $\pi_4 = 4$

Результат: $\pi = (1, 2, 3, 4)$

##### 5.5.4.2. Sampling дискретизація

**Алгоритм:**

Замість argmax, на кожному кроці вибираємо місто **випадково** згідно з розподілом ймовірностей:

$$\pi_k \sim \text{Categorical}(P_{\pi_{k-1}, \cdot})$$

Де $\text{Categorical}$ — категорійний розподіл (multinomial distribution).

**Математична формалізація:**

$$\pi_1 = i_0$$

$$P(\pi_k = j | \pi_{<k}) = \begin{cases}
\frac{P_{\pi_{k-1}, j}}{\sum_{l \notin \text{visited}} P_{\pi_{k-1}, l}} & \text{якщо } j \notin \text{visited} \\
0 & \text{інакше}
\end{cases}$$

**Властивості:**

- **Стохастичний:** Для однієї матриці $P$ може давати різні результати
- **Дослідницький:** Може знаходити кращі рішення, які greedy пропускає
- **Різноманітність:** Дозволяє генерувати кілька кандидатів і вибирати найкращий

**Реалізація (псевдокод):**

```python
def sample_route(P, start=0):
    N = P.shape[0]
    pi = [start]
    visited = {start}
    
    for k in range(1, N):
        current = pi[-1]
        # Нормалізуємо ймовірності для невідвіданих міст
        probs = P[current, :].copy()
        probs[list(visited)] = 0  # Маскуємо відвідані
        probs = probs / probs.sum()  # Нормалізація
        
        # Випадковий вибір згідно з розподілом
        next_city = np.random.choice(N, p=probs)
        pi.append(next_city)
        visited.add(next_city)
    
    return pi
```

##### 5.5.4.3. Temperature-контрольований sampling

Для контролю "гострості" розподілу використовуємо **temperature parameter** $T$:

$$P_{ij}^{(T)} = \frac{\exp(\text{score}_{ij} / T)}{\sum_{k=1}^{N} \exp(\text{score}_{ik} / T)}$$

**Властивості temperature:**

- $T \to 0$: Розподіл стає "гострим" (близький до argmax)
- $T = 1$: Стандартний softmax
- $T \to \infty$: Розподіл стає рівномірним (максимальна ентропія)

**Застосування:**

- **Низька temperature ($T < 1$):** Для експлуатації — вибір близький до найкращого
- **Висока temperature ($T > 1$):** Для дослідження — більше різноманітності

##### 5.5.4.4. Nucleus (Top-p) sampling

Замість вибору з усіх міст, обмежуємо вибір до **nucleus** — найменшої множини міст, сума ймовірностей яких перевищує поріг $p$:

$$\text{Nucleus} = \left\{j : \sum_{i \in \text{sorted}} P_{ij} \le p\right\}$$

Де `sorted` — міста, відсортовані за спаданням ймовірності.

**Переваги:**

- Автоматично адаптується до "гострості" розподілу
- Уникає вибору міст з дуже низькою ймовірністю
- Більш стабільний за temperature sampling

##### 5.5.4.5. Autoregressive vs Non-Autoregressive дискретизація

**Важливе зауваження:** Усі описані вище методи (argmax, sampling) працюють в **autoregressive** режимі — на кожному кроці $k$ ми використовуємо інформацію про попередні кроки $\pi_{<k}$.

**Autoregressive підхід:**

Матриця $P$ може **змінюватися** на кожному кроці залежно від вже побудованого часткового маршруту:

$$P^{(k)}_{ij} = f(\mathbf{h}_i, \mathbf{h}_j, \pi_{<k}, \mathbf{D})$$

Де $f$ — функція, яка враховує:
- Поточні embeddings міст $\mathbf{h}_i, \mathbf{h}_j$
- Вже побудований частковий маршрут $\pi_{<k}$
- Pairwise representation $\mathbf{D}$ (відстані, обмеження тощо)

**Non-Autoregressive підхід (альтернатива):**

Можна також обчислити матрицю $P$ **один раз** для всієї задачі, а потім застосувати дискретизацію. Це швидше, але менш гнучко.

**Порівняння:**

| Підхід | Швидкість | Якість | Гнучкість |
|--------|-----------|--------|-----------|
| **Autoregressive** | Повільніше ($N$ forward passes) | Краща (враховує контекст) | Висока |
| **Non-Autoregressive** | Швидше (1 forward pass) | Гірша | Низька |

**Для VRP/TSP:** Зазвичай використовується autoregressive підхід, оскільки оптимальний вибір наступного міста залежить від вже побудованого маршруту (наприклад, залишкова вантажопідйомність, час тощо).

#### 5.5.5. Методи інференції: Greedy Decoding, Beam Search та Sampling

**Ключове питання:** Як різні методи інференції перетворюють ймовірності $P_{ij}$ на реальний маршрут, і які їх переваги та недоліки?

##### 5.5.5.1. Greedy Decoding (Argmax)

**Опис:**

На кожному кроці вибираємо місто з найвищою ймовірністю переходу з поточного міста.

**Алгоритм:**

```python
def greedy_decode(P, start=0):
    """
    P: [N, N] - ймовірнісна матриця переходів
    start: початкове місто
    """
    N = P.shape[0]
    pi = [start]
    visited = {start}
    
    current = start
    for _ in range(N - 1):
        # Маскуємо відвідані міста
        probs = P[current, :].copy()
        probs[list(visited)] = -np.inf
        
        # Argmax
        next_city = np.argmax(probs)
        pi.append(next_city)
        visited.add(next_city)
        current = next_city
    
    return pi
```

**Математична формалізація:**

$$\pi_1 = \text{start}$$

$$\pi_k = \arg\max_{j \notin \{\pi_1, \dots, \pi_{k-1}\}} P_{\pi_{k-1}, j}$$

**Властивості:**

| Властивість | Значення |
|------------|----------|
| **Детермінізм** | Повністю детерміністичний |
| **Швидкість** | $O(N^2)$ — дуже швидкий |
| **Пам'ять** | $O(N)$ — мінімальна |
| **Якість** | Може бути субоптимальною (локальні оптимуми) |
| **Застосування** | Production systems, real-time inference |

**Переваги:**

- ✅ Найшвидший метод
- ✅ Детерміністичний (відтворювані результати)
- ✅ Мінімальні вимоги до пам'яті
- ✅ Простий у реалізації

**Недоліки:**

- ❌ Може "застрягнути" в локальних оптимумах
- ❌ Не враховує глобальну структуру маршруту
- ❌ Чутливий до помилок моделі на ранніх кроках

**Приклад проблеми:**

Нехай матриця $P$:
```
        місто1  місто2  місто3  місто4
місто1   0.0    0.51    0.49    0.00
місто2   0.30   0.0     0.35    0.35
місто3   0.30   0.35    0.0     0.35
місто4   0.50   0.25    0.25    0.0
```

Greedy: $1 \to 2 \to 3 \to 4$ (можливо субоптимальний)
Оптимальний: $1 \to 3 \to 2 \to 4$ (можливо кращий)

##### 5.5.5.2. Beam Search

**Опис:**

Зберігає $B$ найкращих часткових маршрутів на кожному кроці, а не тільки один.

**Алгоритм:**

```python
def beam_search(P, start=0, beam_width=5):
    """
    P: [N, N] - ймовірнісна матриця переходів
    start: початкове місто
    beam_width: кількість зберігаємих гілок
    """
    N = P.shape[0]
    
    # Ініціалізація: починаємо з одного часткового маршруту
    beams = [([start], {start}, 0.0)]  # (маршрут, відвідані, лог-ймовірність)
    
    for step in range(N - 1):
        candidates = []
        
        # Розширюємо кожен beam
        for route, visited, log_prob in beams:
            current = route[-1]
            
            # Генеруємо всі можливі продовження
            for next_city in range(N):
                if next_city not in visited:
                    new_log_prob = log_prob + np.log(P[current, next_city] + 1e-10)
                    candidates.append((
                        route + [next_city],
                        visited | {next_city},
                        new_log_prob
                    ))
        
        # Вибір топ-B кандидатів за лог-ймовірністю
        candidates.sort(key=lambda x: x[2], reverse=True)
        beams = candidates[:beam_width]
    
    # Повертаємо найкращий повний маршрут
    return beams[0][0]
```

**Математична формалізація:**

Beam Search підтримує множину $B$ часткових маршрутів $\{\pi^{(1)}, \pi^{(2)}, \dots, \pi^{(B)}\}$.

На кожному кроці $k$:
1. Розширюємо кожен частковий маршрут $\pi^{(b)}$ на всі можливі наступні міста
2. Обчислюємо лог-ймовірність: $\log P(\pi^{(b)}_{1:k}) = \sum_{i=1}^{k-1} \log P_{\pi^{(b)}_i, \pi^{(b)}_{i+1}}$
3. Вибераємо топ-$B$ маршрутів за лог-ймовірністю

**Властивості:**

| Властивість | Значення |
|------------|----------|
| **Детермінізм** | Детерміністичний (для фіксованого $B$) |
| **Швидкість** | $O(B \cdot N^2)$ — повільніший за greedy |
| **Пам'ять** | $O(B \cdot N)$ — потребує зберігати $B$ маршрутів |
| **Якість** | Краща за greedy (враховує більше варіантів) |
| **Застосування** | Коли потрібна краща якість за прийнятний час |

**Переваги:**

- ✅ Краща якість за greedy (враховує більше варіантів)
- ✅ Детерміністичний
- ✅ Контрольований компроміс між якістю та швидкістю (через $B$)

**Недоліки:**

- ❌ Повільніший за greedy ($B$ разів)
- ❌ Потребує більше пам'яті
- ❌ Може все ще пропускати оптимальні рішення (якщо вони не в топ-$B$)

**Вибір beam width:**

- $B = 1$: Еквівалентно greedy decoding
- $B = 5-10$: Хороший компроміс для більшості задач
- $B = N$: Еквівалентно повному пошуку (експоненційно повільно)

##### 5.5.5.3. Sampling (Stochastic Decoding)

**Опис:**

На кожному кроці вибираємо місто випадково згідно з розподілом ймовірностей.

**Алгоритм:**

```python
def sample_decode(P, start=0, temperature=1.0):
    """
    P: [N, N] - ймовірнісна матриця переходів
    start: початкове місто
    temperature: контроль "гострості" розподілу
    """
    N = P.shape[0]
    pi = [start]
    visited = {start}
    current = start
    
    for _ in range(N - 1):
        # Отримуємо розподіл для поточного міста
        probs = P[current, :].copy()
        probs[list(visited)] = 0
        
        # Застосовуємо temperature
        if temperature != 1.0:
            probs = np.power(probs, 1.0 / temperature)
        
        # Нормалізація
        probs = probs / (probs.sum() + 1e-10)
        
        # Випадковий вибір
        next_city = np.random.choice(N, p=probs)
        pi.append(next_city)
        visited.add(next_city)
        current = next_city
    
    return pi
```

**Математична формалізація:**

$$\pi_1 = \text{start}$$

$$P(\pi_k = j | \pi_{<k}) = \frac{P_{\pi_{k-1}, j}^{(T)}}{\sum_{l \notin \text{visited}} P_{\pi_{k-1}, l}^{(T)}}$$

Де $P^{(T)}$ — temperature-контрольований розподіл.

**Властивості:**

| Властивість | Значення |
|------------|----------|
| **Детермінізм** | Стохастичний (різні результати при кожному запуску) |
| **Швидкість** | $O(N^2)$ — така ж як greedy |
| **Пам'ять** | $O(N)$ — мінімальна |
| **Якість** | Може знаходити кращі рішення через дослідження |
| **Застосування** | Коли потрібна різноманітність, генерація кількох кандидатів |

**Переваги:**

- ✅ Може знаходити кращі рішення (через дослідження простору)
- ✅ Швидкий (така ж складність як greedy)
- ✅ Дозволяє генерувати кілька кандидатів і вибирати найкращий
- ✅ Корисний для навчання через reinforcement learning

**Недоліки:**

- ❌ Не детерміністичний
- ❌ Може генерувати погані рішення (через випадковість)
- ❌ Потребує багаторазової генерації для надійності

**Стратегія "Sample and Select":**

1. Генеруємо $K$ маршрутів через sampling
2. Обчислюємо вартість кожного: $C(\pi^{(1)}), C(\pi^{(2)}), \dots, C(\pi^{(K)})$
3. Вибираємо найкращий: $\pi^* = \arg\min_k C(\pi^{(k)})$

Це часто дає кращі результати за greedy, особливо коли модель не дуже впевнена.

##### 5.5.5.4. Порівняння методів

**Таблиця порівняння:**

| Метод | Швидкість | Пам'ять | Якість | Детермінізм | Застосування |
|-------|-----------|---------|--------|------------|--------------|
| **Greedy** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ✅ | Production, real-time |
| **Beam Search** | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ | ✅ | Коли потрібна краща якість |
| **Sampling** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ❌ | Дослідження, RL training |
| **Sample & Select** | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ❌ | Коли потрібна найкраща якість |

**Рекомендації:**

1. **Production systems:** Greedy decoding (швидкість + детермінізм)
2. **Офлайн оптимізація:** Beam Search з $B=5-10$ (компроміс якість/швидкість)
3. **Навчання через RL:** Sampling (дослідження простору)
4. **Найкраща якість:** Sample & Select з $K=100-1000$ (якщо час дозволяє)

**Математичне обґрунтування:**

Нехай $\pi^*$ — оптимальний маршрут, а $\pi_{method}$ — маршрут, отриманий методом.

**Greedy:**
$$E[C(\pi_{greedy})] \ge C(\pi^*)$$
(Може бути довільно поганим у гіршому випадку)

**Beam Search:**
$$C(\pi_{beam}) \le C(\pi_{greedy})$$
(Завжди не гірший за greedy, оскільки greedy — це beam search з $B=1$)

**Sampling:**
$$P(C(\pi_{sample}) \le C(\pi_{greedy})) > 0$$
(З ненульовою ймовірністю може знайти краще рішення)

**Sample & Select:**
$$E[\min_k C(\pi^{(k)}_{sample})] \le E[C(\pi_{greedy})]$$
(Очікувана вартість найкращого з $K$ зразків не гірша за greedy)

#### 5.5.6. Чому це працює: Теоретичне обґрунтування

**Теорема (наближення дискретної оптимізації):**
Якщо ймовірнісна матриця $P$ має **високий пік** (одна ймовірність набагато більша за інші), то дискретизація через argmax дає рішення, близьке до оптимального.

**Формалізація:**
Нехай $P^*$ — оптимальна ймовірнісна матриця (навчена на оптимальних маршрутах). Якщо:
$$\max_j P^*_{ij} \ge 1 - \epsilon \quad \text{для всіх } i$$

То маршрут, побудований через argmax, має вартість:
$$C(\pi_{argmax}) \le (1 + \delta) \cdot C(\pi^*)$$

Де $\delta \to 0$ при $\epsilon \to 0$.

**Висновок:** Якщо модель навчається добре, ймовірнісна матриця стає "гострою" (spiky), і дискретизація дає близьке до оптимального рішення.

**Для VRP/TSP:**
- Attention механізм навчається виявляти **паттерни** в оптимальних маршрутах
- Після навчання, ваги attention автоматично формують матрицю $P$, яка "віддає перевагу" оптимальним переходам
- М'які обмеження дозволяють моделі експериментувати під час навчання, але "штовхають" до валідних рішень

## 7. Обмеження та trade-offs

### 7.1. Точність vs Швидкість

**Комбінаторний підхід:**
- Точність: 100% (глобальний оптимум)
- Швидкість: Експоненційна (години-роки для великих задач)

**Геометричний підхід:**
- Точність: 95-99% (наближення)
- Швидкість: Поліноміальна (мілісекунди-секунди)

**Висновок:** Для практичних застосувань 95-99% точності за мілісекунди краще за 100% точності за роки.

### 7.2. Потребує навчання

**Комбінаторний підхід:**
- Не потребує навчання
- Працює "з коробки" для будь-якої задачі

**Геометричний підхід:**
- Потребує навчання на даних
- Потребує великий датасет оптимальних рішень

**Проблема:** Для нових типів задач може не бути датасету.

**Рішення:** Transfer learning — навчити на одних задачах, адаптувати для інших.

### 7.3. Інтерпретація

**Комбінаторний підхід:**
- Рішення легко інтерпретувати (наприклад, послідовність відвідування)
- Можна довести оптимальність

**Геометричний підхід:**
- Рішення важче інтерпретувати (embeddings, attention weights)
- Неможливо довести оптимальність (лише емпірична валідація)

**Висновок:** Для критичних застосувань (наприклад, медицина) може знадобитися комбінація обох підходів.

## 8. Engineering Challenge: AI-Resistant Assessment

### 8.1. Задача: Проектування універсального солвера для NP-повних задач

**Контекст:**
Ви працюєте над системою, яка має вирішувати різні NP-повні задачі (TSP, VRP, Job Scheduling, Graph Coloring) для різних клієнтів.

**Вимоги:**
- **Універсальність:** Система має працювати для різних типів NP-повних задач
- **Масштабованість:** Підтримка задач з $N=10$ до $N=10,000$
- **Latency:** Генерація рішення: $<1$ секунда для $N=100$, $<10$ секунд для $N=1,000$
- **Точність:** 95-99% від оптимуму (прийнятно для практики)
- **Обмеження:**
  - Бюджет: 1 сервер (64 CPU cores, 256 GB RAM, 4× NVIDIA A100 GPU)
  - Модель має займати $<80$ GB пам'яті (залишаємо місце для даних)

**Технічні деталі:**
- Різні типи задач мають різну структуру (графи, обмеження)
- Немає універсального датасету для всіх типів задач
- Деякі задачі потребують точного рішення (100%), інші — наближеного (95%+)

**Ваше завдання:**

1. **Виберіть архітектуру:**
   - A) Окрема модель для кожного типу задач (спеціалізовані моделі)
   - B) Універсальна модель з адаптивними компонентами (transfer learning)
   - C) Hybrid: Класичні алгоритми для малих задач ($N<50$), Deep Learning для великих
   - D) Meta-learning: Модель, яка навчається адаптуватися до нових задач

2. **Обґрунтуйте вибір через метрики:**
   - Розрахуйте складність навчання для кожного варіанту
   - Оцініть latency для різних типів задач та розмірів
   - Порахуйте вартість підтримки системи

3. **Захистіть рішення:**
   - Чому ваш підхід кращий за альтернативи?
   - Як система обробляє нові типи задач (zero-shot learning)?
   - Які trade-offs ви прийняли (універсальність vs точність vs швидкість)?

**Критерії оцінки:**
- **Недостатньо:** "Використаємо AlphaFold 2 для всіх задач" (немає аналізу адаптації)
- **Добре:** Розрахунок складності та latency для різних типів задач
- **Відмінно:** Аналіз trade-offs, стратегія для нових задач, обґрунтування через метрики

### 8.2. Референсне рішення (для викладача)

**Рекомендована архітектура: C) Hybrid (класичні + Deep Learning)**

**Обґрунтування:**

**Компонент 1: Класичні алгоритми (для $N < 50$)**
- **TSP:** Held-Karp (DP) або Branch & Bound
- **VRP:** Gurobi Optimizer
- **Job Scheduling:** Constraint Programming
- **Переваги:** 100% точність, не потребує навчання
- **Latency:** Секунди-хвилини (прийнятно для малих задач)

**Компонент 2: Deep Learning (для $N \ge 50$)**
- **Архітектура:** Адаптована AlphaFold 2
- **Навчання:** Окрема модель для кожного типу задач (спеціалізація)
- **Переваги:** Швидкість (мілісекунди-секунди), масштабованість
- **Точність:** 95-99% (прийнятно для великих задач)

**Компонент 3: Meta-Learning для нових задач**
- **Few-shot learning:** Навчання на 10-100 прикладах нової задачі
- **Transfer learning:** Використання знань з подібних задач
- **Переваги:** Швидка адаптація до нових задач

**Загальна система:**
- **Розподіл навантаження:**
  - 20% задач мають $N < 50$ → класичні алгоритми
  - 80% задач мають $N \ge 50$ → Deep Learning
- **Latency:**
  - Малі задачі: $P_{50}=5$ секунд, $P_{99}=30$ секунд
  - Великі задачі: $P_{50}=0.5$ секунди, $P_{99}=5$ секунд
- **Точність:**
  - Малі задачі: 100% (глобальний оптимум)
  - Великі задачі: 95-99% (наближення)

**Порівняння з альтернативами:**

**A) Окрема модель для кожного типу:**
- Пам'ять: 4 типи задач × 20 GB = 80 GB (в межах бюджету) ✅
- Навчання: Потребує датасет для кожного типу ❌
- **Висновок:** Працює, але потребує багато даних

**B) Універсальна модель:**
- Пам'ять: 80 GB (в межах) ✅
- Навчання: Складніше (потребує датасет для всіх типів) ❌
- Точність: Може бути нижчою (компроміс між типами) ⚠️

**D) Meta-learning:**
- Складність навчання: Дуже висока (потребує багато різних задач) ❌
- Адаптація: Швидка для нових задач ✅
- **Висновок:** Перспективно, але складно реалізувати

**Масштабування:**
Для більшої кількості типів задач можна додати більше GPU або використати model compression (квантизація, pruning).
