# 05. Control Regimes & Experimental Scenarios

**Scope:** Definition of simulation modes (Baseline vs. Optimized) and intervention logic.
**Input:** Graph state $G(t)$, Agent population $A$.
**Output:** Modified Edge Weights $W'(t)$ or Forced Paths $P_{forced}$.

## 1. Концепція експерименту

Ми розглядаємо евакуацію як порівняння ефективності двох фундаментальних принципів розподілу потоків. Мета — кількісно виміряти **Price of Anarchy (PoA)**:

$$PoA = \frac{\text{Total Time (User Equilibrium)}}{\text{Total Time (System Optimum)}}$$

---

## 2. Regime A: Unmanaged (Wardrop's User Equilibrium)

**Logic: Wardrop's First Principle**
Цей режим моделює природну поведінку водіїв. Згідно з першим принципом Вардропа:
> "Трафік розподіляється так, що час подорожі по всіх використовуваних маршрутах є однаковим і мінімальним для кожного окремого користувача. Жоден водій не може зменшити свій час, змінивши маршрут в односторонньому порядку".

У цьому стані кожен агент $a_i$ діє егоїстично, мінімізуючи власну вартість $Cost_i$.

* **Information Scope:** Агент знає лише *власну* позицію, ціль та видимий стан поточного/сусіднього ребра.
* **Routing Logic:** Greedy Best-First або Local $A^*$.
* **Re-routing:** Тригер перерахунку маршруту спрацьовує, коли $v_{curr} < v_{threshold}$ протягом часу $t_{patience}$.
* **Наслідок (The Trap):** Хоча це рівноважний стан, він не є оптимальним. Усі обирають "найшвидшу" центральну магістраль, що призводить до її перенасичення (Braess's paradox), тоді як довші альтернативні маршрути залишаються порожніми.

---

## 3. Regime B: Hybrid / Infrastructure Control

**Логіка:** "Регулювання потоків".
Система не керує машинами, але керує мережею (світлофори, поліцейські блокпости, реверсивний рух).

### 3.1. Dynamic Weight & Cognitive Filtering (The Vacuum Effect)
Глобальний контролер намагається керувати потоком, змінюючи "вартість" ребер (віртуальні затори на картах, заборонні знаки). Однак реакція на це втручання залежить від психотипу агента.

**Intervention Logic:**
Якщо щільність $\rho_e > \rho_{crit}$, контролер додає до ребра штрафну вагу $P_{admin}$ (Administrative Penalty).

**Agent Reaction (Split Cost Function):**
1.  **Compliant Agent ($\alpha=1$):**
    Довіряє навігатору. Бачить $Cost = T_{phys} + P_{admin}$. Обирає об'їзд.
2.  **Rogue Agent ($\alpha=0$):**
    Ігнорує віртуальні обмеження. Бачить $Cost = T_{phys}$.

**Phenomenon: The "Vacuum Effect"**
Адміністративне "закриття" дороги працює як фільтр: воно прибирає законослухняних водіїв, звільняючи фізичний простір. Оскільки $\rho_e$ падає, *Rogue* агент бачить це як "раптово вільну трасу" і спрямовується туди.

> **Scientific Implication (Game Theory):**
> У цьому сценарії виникає парадокс: система регулювання мимоволі винагороджує порушників.
> * *Гіпотеза:* У режимі Hybrid Control стратегія $\alpha=0$ (Rogue) може стати домінуючою стратегією виживання ($S_{rate}^{rogue} \gg S_{rate}^{compliant}$).
> * *Інтерпретація:* Слухняні агенти "платять" своїм часом і ризиком (їдучи в об'їзд), субсидуючи швидкий виїзд порушників по прямій. Це фундаментальна проблема справедливості алгоритмів (Algorithmic Fairness).

### 3.2. Contraflow Activation (Реверс)
У цьому режимі дозволяється динамічна зміна топології.
* **Condition:** Якщо вихідний потік з міста на магістралі М1 < 10% від вхідного (зустрічного), а вхідний стоїть.
* **Action:** Ребро $(u, v)$ з атрибутом `oneway=True` отримує атрибут `reversed=True`.
* **Safety Constraints:** Потрібен "Clearance Time" (час на звільнення смуги), перш ніж пустити потік назустріч. У симуляції це затримка $T_{clear} = 15$ хв.

## 4. Regime C: Prescriptive (System Optimum)

**Logic: Omniscient Centralized Control**
У цьому режимі ми припускаємо наявність центрального контролера, що володіє повною інформацією про стан системи (Omniscient Authority).
Мета контролера — мінімізувати середній час евакуації $\sum T_i$, навіть якщо це вимагає пожертвувати інтересами окремих агентів.

### 4.1. Fuel-Aware Load Balancing
Це не просто навігація, а система розподілу обмежених ресурсів. Головна етична проблема алгоритмів System Optimum — "Fatal Routing", коли система жертвує одним агентом заради прискорення решти.

Ми впроваджуємо **Conditional Routing Protocol**:

1.  **Feasibility Constraint:**
    Система не має права призначити агенту $a_i$ маршрут $P$, якщо очікувана витрата перевищує його запас:
    $$Cost_{fuel}(P) > f_i(t) - f_{safety}$$
    Такі маршрути виключаються з простору пошуку для конкретного агента.

2.  **Resource-based Segregation (Triage):**
    * **Critical Agents ($f < 30\%$):** Отримують пріоритетний доступ до **найкоротших** (Geodesic) маршрутів. Система "розчищає" їм дорогу.
    * **Donor Agents ($f > 70\%$):** Виступають донорами стабільності. Система агресивно перенаправляє їх на **довгі об'їзні маршрути** (Detours).

### 4.2. Staggered Departure (Управління стартом)
Якщо магістраль перевантажена, система видає команду `HOLD` агентам у зонах спавну.
* **Принцип:** Краще чекати вдома з вимкненим двигуном ($Fuel = const$), ніж спалювати ресурс у заторі ($Fuel \downarrow$).
* **Trade-off:** Це зменшує Gridlock Index, але збільшує індивідуальний час очікування.

## 5. Матриця Експериментів (Test Cases)

Для отримання валідних даних необхідно провести серію прогонів (Batch Run) зі зміною змінних.

| Змінна | Діапазон значень | Опис |
| :--- | :--- | :--- |
| **Population ($N$)** | 1k, 5k, 10k, 20k | Стрес-тест масштабованості. |
| **Rogue Ratio ($R$)** | 0%, 10%, 30%, 50% | Вплив порушників на System Optimum. |
| **Compliance ($\alpha$)** | 100% $\to$ 20% | Чутливість режиму C до недовіри населення. |
| **Fuel Constraints** | Off / On | Оцінка впливу "мертвих" машин на потік. |

### Monte Carlo Simulation
Оскільки система містить стохастичні елементи (аварії, час реакції), кожен сценарій проганяється $K=10$ разів. Результат усереднюється, будується довірчий інтервал (Confidence Interval).

## 6. Implementation Architecture

Реалізація логіки управління вимагає патерну **Strategy**.

```python
class SimulationEngine:
    def step(self):
        # 1. Physics Update
        self.update_positions_and_fuel()
        
        # 2. Control Strategy (Polymorphic)
        # Regime A: Do nothing
        # Regime B: Update edge weights
        # Regime C: Push new paths to agents
        self.control_strategy.apply(self.graph, self.agents)
        
        # 3. Agent Decisions
        for agent in self.agents:
            agent.decide()
```

Ця архітектура дозволяє легко перемикати режими без переписування коду агентів.
