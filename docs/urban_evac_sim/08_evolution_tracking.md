# 08. Evolution & Benchmark History

**Scope:** Continuous Integration for Algorithm Performance.
**Goal:** Track the impact of every code change on Survival Rates.

## 1. Філософія: "Code as a hypothesis"

У цьому проекті кожна зміна коду (зміна ваги ребра, новий алгоритм для Rogue-агентів) є гіпотезою.
* *Гіпотеза:* "Якщо ми заборонимо ліві повороти на вулиці Х, затор зменшиться".
* *Перевірка:* Ми повинні бачити це не на око, а на дельті метрик.

Ми будуємо **History of Optimization** — лог того, як "розумнішала" наша система.

---

## 2. Benchmark Log (Leaderboard)

Система повинна автоматично вести журнал експериментів (`experiments.csv`).
Кожен рядок — це "зліпок" ефективності системи на певній версії коду.

### Структура Журналу:
| Run ID | Git Commit | Description | Pop ($N$) | Regime | Clearance Time ($T_{99}$) | Survival Rate ($S$) | Fuel Casualties |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **001** | `a1b2c3` | MVP: Random Walk | 1k | Chaos | ∞ (Timeout) | 12% | 0 (No fuel logic) |
| **002** | `d4e5f6` | Added A* Routing | 1k | Chaos | 45 min | 85% | 0 |
| **003** | `g7h8i9` | Added Fuel Physics | 1k | Chaos | 62 min | 70% | 142 agents |
| **...** | ... | ... | ... | ... | ... | ... | ... |
| **015** | `x1y2z3` | Prescriptive Logic v1 | 10k | Managed | 38 min | 94% | 12 agents |

### Правило "Green Delta"
Кожен новий PR (Pull Request) або суттєва зміна алгоритму має супроводжуватися звітом:
> "Зміна алгоритму світлофорів покращила $T_{99}$ на 5% (з 40хв до 38хв), але збільшила $G_{idx}$ на 2% у спальному районі".

## 3. Comparative Visualization (Evolution Graph)

На фінальному захисті курсової ми показуємо не одну точку, а **графік прогресу**.

### Осі графіка:
* **X:** Час розробки (або версії моделі).
* **Y:** Час евакуації ($T_{99}$).

### Що ми хочемо побачити?
1.  **Початковий Хаос:** Високі значення $T_{99}$, низький $S_{rate}$.
2.  **Впровадження фізики:** Тимчасове погіршення показників (симуляція стала реалістичнішою, агенти почали "вмирати" без палива).
3.  **Впровадження Control:** Різке покращення (Drop) часу евакуації.
4.  **Fine-tuning:** Повільне асимптотичне покращення за рахунок мікро-оптимізацій.

---

## 4. Regression Testing (Захист від деградації)

Коли студент намагається покращити поведінку *Rogue Agents*, він може випадково зламати логіку *Compliant Agents*.

**Вимога:**
Перед кожним комітом запускається "Mini-Benchmark" (наприклад, на 1000 агентів).
* Якщо $S_{rate}$ впав більше ніж на 5% порівняно з `HEAD` — **Build Failed**.
* Це гарантує, що ми рухаємось вперед, а не ходимо колами.

## 5. Artifacts

Результат роботи цього модуля — **"Звіт про еволюцію"** (Markdown/PDF), де для кожного стрибка ефективності є пояснення:
* *"У версії 0.4 ми додали 'Backpressure Awareness'. Агенти перестали їхати на перехрестя, якщо за ним затор. Це зменшило кількість Deadlocks на 80%."*

Це показує інженерне мислення: не просто "написав код", а "дослідив проблему -> висунув гіпотезу -> реалізував -> виміряв результат".
