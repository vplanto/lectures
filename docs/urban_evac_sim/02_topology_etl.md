# 02. Topology ETL Pipeline

**Scope:** Data ingestion, Graph Engineering, and Static Weight calculation.
**Input:** OpenStreetMap (OSM) raw data.
**Output:** Optimized Routing Graph ($G_{opt}$) & Zoning Map.

## 1. Концепція ETL

Сирі дані OSM є картографічними, а не навігаційними. Вони містять надмірну деталізацію (поворот дороги може складатися з 50 вузлів), яка експоненційно збільшує простір пошуку для алгоритмів маршрутизації.

Мета цього етапу — **Graph Contraction** (стиснення графа) та збагачення його фізичними атрибутами для симуляції.

### Pipeline Steps:
1.  **Ingestion:** Завантаження геометрії в межах полігону міста.
2.  **Pruning & Simplification:** Видалення топологічного шуму.
3.  **Attribute Injection:** Розрахунок статичної пропускної здатності.
4.  **Zoning:** Розмітка зон спавну (Sources) та евакуації (Sinks).

---

## 2. Алгоритми спрощення (Topology Engineering)

Ми трансформуємо сирий граф $G_{raw}=(V, E)$ у оптимізований граф $G_{opt}=(V', E')$.

### 2.1. Topological Simplification (Smart Contraction)
Вузли $v \in V$, що мають ступінь $deg(v) = 2$ (тобто є лише з'єднувачами геометрії без перехресть), підлягають умовному видаленню.

Ми застосовуємо алгоритм **Conditional Merge**: ребра $(u, v)$ та $(v, w)$ об'єднуються в одне $(u, w)$ *тільки* при виконанні умов:
1.  **Topology:** Вузол $v$ не є джерелом або стоком (Source/Sink).
2.  **Granularity Constraint:** Сумарна довжина нового ребра $L_{uw} < L_{max}$ (рекомендовано 500м).

**Why Limit Length?**
Проблема "Довгого ребра" (Long Edge Risk). Якщо об'єднати вулицю в одне ребро довжиною 5 км, а затор утворився лише на останніх 100 метрах перед світлофором, математична щільність $\rho = N/L$ буде низькою (наприклад, 0.1). Алгоритм $A^*$ помилково вважатиме ребро "вільним" і спрямує туди потік.
Обмеження $L_{max}$ гарантує **дискретизацію заторів**: ми бачимо локальний затор на конкретному сегменті, а не усереднений по всій магістралі.

**Результат:**
* Збереження гранулярності для heatmap.
* Зменшення кількості вузлів на ~60-70% (замість агресивних 90%).

### 2.2. Cleaning Artifacts
* **Strongly Connected Components:** Видалення ізольованих підграфів (наприклад, дороги всередині закритих територій, які не мають виходу до головної мережі), що не досягають множини виходів $S_{sinks}$.
* **Loop Removal:** Видалення петель $u \to u$ (розворотів на місці), якщо вони не є критичними розв'язками.

## 3. Модель ваги ребер (Static Edge Physics)

Кожне ребро $e \in E'$ отримує статичний вектор атрибутів, що визначає його фізику до початку симуляції.

### 3.1. Capacity Estimation
OSM часто не містить тегу `lanes`. Ми використовуємо евристику імпутації на основі тегу `highway`:
* `motorway` / `trunk`: 3 смуги.
* `primary` / `secondary`: 2 смуги.
* `residential` / `tertiary`: 1 смуга.

**Пропускна здатність ребра (Static Capacity):**
$$C_{max}(e) = N_{lanes} \cdot L_e \cdot \gamma_{packing}$$
Де $\gamma_{packing}$ — середня довжина авто з урахуванням безпечної дистанції (~7.5м). Це визначає, скільки агентів фізично поміститься на ребрі (Gridlock limit).

### 3.2. Base Cost Function
Базова вартість проходження (без заторів) для $A^*$:
$$W_{static}(e) = \frac{L_e}{V_{limit} \cdot \delta_{surface}}$$
Де $\delta_{surface}$ — коефіцієнт якості покриття (1.0 для асфальту, 0.6 для ґрунтових доріг, що важливо для сільської місцевості у воєнний час).

## 4. Зонування та Макро-граф (Macro-Topology)

Для оптимізації та масштабування ми накладаємо на граф "сітку" або семантичні шари.

### 4.1. Spawn Zones (Sources)
Використовуємо полігони `landuse=residential` та `landuse=commercial` з OSM.
* Вузли графа, що потрапляють у полігон, маркуються тегом `zone_id`.
* Спавн агентів відбувається не в точці, а в радіусі $R$ навколо вузлів зони.

### 4.2. Evacuation Sinks (Exits)
Визначаються вручну або алгоритмічно як вузли на периметрі bounding box, що мають вихідні ребра типу `primary` або `trunk`.
* Агент вважається врятованим, якщо досяг $v \in S_{sinks}$.

---

## 5. Формат артефактів (Artifacts Definition)

Результатом роботи ETL є файл `city_topology.graphml` (або `.pickle`), що містить граф `NetworkX` з наступними атрибутами:

**Node Attributes:**
* `id`: int64
* `x`, `y`: float (Web Mercator projection)
* `type`: {`intersection`, `source`, `sink`}

**Edge Attributes:**
* `length`: float (метри)
* `max_speed`: int (км/год)
* `lanes`: int
* `capacity`: int (макс. кількість машин)
* `geometry`: LineString (для візуалізації)

## 6. Технічні ризики (Edge Cases)

1.  **Broken Topology:** В OSM дорога може візуально перетинатися, але не мати спільного вузла (міст над дорогою без з'їзду). Алгоритм має довіряти топології, а не геометрії.
2.  **One-way Streets:** Критично важливо враховувати тег `oneway`. У режимі "Prescriptive" (Scenario B) ми можемо програмно ігнорувати цей тег для створення реверсивного руху (Contraflow).
