## Методологічний контекст

### Проблема традиційного моніторингу

Традиційні системи моніторингу IT-інфраструктур використовують **порогові значення (thresholds)** для виявлення аномалій:

```
if cpu_usage > 80%:
    alert("CPU overload!")
```

**Обмеження цього підходу:**
- ❌ Статичні пороги не враховують контекст системи
- ❌ Високе CPU може бути нормальним для навантажених серверів
- ❌ Неможливо виявити складні взаємозв'язки між метриками
- ❌ Велика кількість хибних спрацювань (false positives)

### Концепція статистичних інваріантів

**Інваріант** — це стійка математична залежність між групами метрик, яка зберігається в "нормальному" стані системи.

**Приклад:** У стабільній системі між CPU та температурою існує лінійна залежність:
```
temperature = 0.5 × cpu_usage + 40°C
```

Якщо ця залежність порушується (наприклад, температура вища за очікувану), це сигналізує про аномалію.

## Математична формалізація

### Крок 1: Зменшення розмірності через PCA

Для кожної логічної групи метрик $\mathbf{X} \in \mathbb{R}^{n \times p}$ (де $n$ — кількість спостережень, $p$ — кількість метрик) застосовуємо **Principal Component Analysis (PCA)**.

#### Стандартизація даних

Спочатку нормалізуємо дані (Z-score normalization):

$$
z_{ij} = \frac{x_{ij} - \mu_j}{\sigma_j}
$$

де:
* $z_{ij}$ — елемент нормалізованої матриці;
* $x_{ij}$ — вихідне значення $i$-го спостереження для $j$-ї метрики;
* $\mu_j$ — середнє значення $j$-ї метрики;
* $\sigma_j$ — стандартне відхилення $j$-ї метрики.

#### PCA трансформація

PCA знаходить ортогональні напрямки максимальної варіативності (Projected Data):

$$
\mathbf{Z} = \mathbf{X}_{\text{scaled}} \mathbf{W}
$$

де:
* $\mathbf{W} \in \mathbb{R}^{p \times k}$ — матриця власних векторів (loadings);
* $\mathbf{Z} \in \mathbb{R}^{n \times k}$ — матриця головних компонент (scores).

#### Вибір кількості компонент

Визначаємо мінімальну кількість компонент $k^*$, що пояснюють $\geq 95\%$ кумулятивної дисперсії (за умови, що власні значення впорядковані $\lambda_1 \ge \lambda_2 \ge \dots \ge \lambda_p$):

$$
k^* = \min \left\{ k : \frac{\sum_{i=1}^{k} \lambda_i}{\sum_{j=1}^{p} \lambda_j} \geq 0.95 \right\}
$$

де $\lambda_i$ — власні значення коваріаційної матриці $\mathbf{C}$:

$$
\mathbf{C} = \frac{1}{n-1}\mathbf{X}_{\text{scaled}}^\top \mathbf{X}_{\text{scaled}}
$$

### Крок 2: Пошук лінійних інваріантів

Для кожної пари трансформованих компонент $(z_x, z_y)$ з різних груп шукаємо лінійну залежність:

$$z_y = a \cdot z_x + b + \epsilon$$

де:
- $a$ — коефіцієнт нахилу
- $b$ — перетин (intercept)
- $\epsilon$ — залишок (residual)

#### Метод найменших квадратів (OLS)

Оцінки параметрів:

$$a = \frac{\text{Cov}(z_x, z_y)}{\text{Var}(z_x)} = \frac{\sum_{i=1}^{n}(z_{x,i} - \bar{z}_x)(z_{y,i} - \bar{z}_y)}{\sum_{i=1}^{n}(z_{x,i} - \bar{z}_x)^2}$$

$$b = \bar{z}_y - a \cdot \bar{z}_x$$

де $\bar{z}_x, \bar{z}_y$ — середні значення компонент.

#### Коефіцієнт кореляції Пірсона

Вимірює силу лінійного зв'язку:

$$r = \frac{\text{Cov}(z_x, z_y)}{\sigma_{z_x} \sigma_{z_y}} = \frac{\sum_{i=1}^{n}(z_{x,i} - \bar{z}_x)(z_{y,i} - \bar{z}_y)}{\sqrt{\sum_{i=1}^{n}(z_{x,i} - \bar{z}_x)^2 \sum_{i=1}^{n}(z_{y,i} - \bar{z}_y)^2}}$$

**Критерій валідності інваріанта:**
$$|r| > 0.93$$

---

### Крок 3: Детекція аномалій

#### Обчислення залишків

Для кожного спостереження $i$:

$$\epsilon_i = |z_{y,i} - (a \cdot z_{x,i} + b)|$$

#### Поріг аномалій

Визначаємо максимальний залишок на тренувальному наборі:

$$\epsilon_{\max} = \max_{i=1,\ldots,n} \epsilon_i$$

Додаємо overhead (запас) для уникнення хибних спрацювань:

$$\tau = \epsilon_{\max} \cdot (1 + \alpha)$$

де $\alpha$ — overhead коефіцієнт (за замовчуванням $\alpha = 0.1$).

#### Правило детекції

Для нового спостереження $(z_x^{\text{new}}, z_y^{\text{new}})$:

$$\text{Аномалія} \Leftrightarrow |z_y^{\text{new}} - (a \cdot z_x^{\text{new}} + b)| > \tau$$

## Алгоритм виявлення інваріантів

### Псевдокод

```
АЛГОРИТМ: InvariantDiscovery

ВХІД:
  - X: DataFrame з метриками
  - G: словник груп ознак {group_name: [features]}
  - θ_var: поріг варіативності (0.95)
  - θ_corr: поріг кореляції (0.93)
  - α: overhead (0.1)

ВИХІД:
  - I: список інваріантів

1. ІНІЦІАЛІЗАЦІЯ:
   I ← []

2. ДЛЯ кожної групи g ∈ G:
   a. X_g ← вибірка ознак групи g з X
   b. X_g_scaled ← стандартизація(X_g)
   c. (W, Z_g, k) ← PCA(X_g_scaled, θ_var)
   d. Зберегти (W, scaler, features) для групи g

3. ДЛЯ кожної пари груп (g_x, g_y), де g_x ≠ g_y:
   a. ДЛЯ кожної компоненти z_x ∈ Z_{g_x}:
      b. ДЛЯ кожної компоненти z_y ∈ Z_{g_y}:
         i. (a, b, r) ← лінійна_регресія(z_x, z_y)
         ii. ЯКЩО |r| ≥ θ_corr:
            - ε_max ← max(|z_y - (a·z_x + b)|)
            - τ ← ε_max · (1 + α)
            - Додати інваріант до I:
              {
                x_component: z_x,
                y_component: z_y,
                coefficient_a: a,
                intercept_b: b,
                correlation: r,
                threshold: τ
              }

4. ПОВЕРНУТИ I
```

## Реалізація в Python

### Клас InvariantDiscovery

```python
from seminar1_invariant_discovery import InvariantDiscovery

# Створення об'єкта
discovery = InvariantDiscovery(
    variance_threshold=0.95,    # ≥95% варіативності
    correlation_threshold=0.93, # |r| > 0.93
    overhead=0.1                # 10% запас
)

# Додавання груп метрик
discovery.add_feature_group(
    'cpu_metrics',
    ['cpu_usage', 'cpu_freq', 'cpu_temp']
)
discovery.add_feature_group(
    'memory_metrics',
    ['ram_usage', 'swap_usage', 'cache_hits']
)

# Навчання
invariants = discovery.fit(training_data)

# Детекція аномалій
results = discovery.detect_anomalies(new_data)
```

### Структура даних Invariant

```python
@dataclass
class Invariant:
    x_component_idx: int      # Індекс PCA компоненти x
    y_component_idx: int       # Індекс PCA компоненти y
    coefficient_a: float       # Коефіцієнт a
    intercept_b: float        # Коефіцієнт b
    correlation: float        # Кореляція r
    max_residual: float       # Максимальний залишок ε_max
    threshold: float          # Поріг τ = ε_max · (1 + α)
```

## Переваги підходу

### 1. Адаптивність
- ✅ Інваріанти автоматично адаптуються до нормальної поведінки системи
- ✅ Не потрібно вручну налаштовувати пороги для кожної метрики

### 2. Виявлення складних залежностей
- ✅ Може виявити неочевидні зв'язки між метриками
- ✅ Враховує взаємодію між групами метрик

### 3. Зменшення хибних спрацювань
- ✅ Порушення інваріанта — більш надійний сигнал, ніж перевищення статичного порогу
- ✅ Overhead коефіцієнт дозволяє налаштувати чутливість

### 4. Інтерпретованість
- ✅ Кожен інваріант має чітку математичну формулу
- ✅ Можна візуалізувати залежність та порушення

---

## Обмеження та обережності

### 1. Залежність від якості даних
- ⚠️ Інваріанти навчаються на історичних даних
- ⚠️ Якщо тренувальні дані містять аномалії, інваріанти будуть некоректними

### 2. Нелінійні залежності
- ⚠️ Метод шукає лише лінійні інваріанти
- ⚠️ Нелінійні залежності можуть бути пропущені

### 3. Витрати на обчислення
- ⚠️ PCA та пошук інваріантів вимагають обчислювальних ресурсів
- ⚠️ Для великих датасетів може знадобитися оптимізація

### 4. Стаціонарність
- ⚠️ Припускається, що "нормальна" поведінка системи стаціонарна
- ⚠️ При зміні конфігурації системи інваріанти потрібно переобучати

## Практичні рекомендації

### Підготовка даних
1. **Очищення:** Видалити явні аномалії з тренувального набору
2. **Нормалізація:** Завжди стандартизувати дані перед PCA
3. **Групування:** Логічно групувати метрики (CPU, Memory, Network)

### Налаштування параметрів
1. **variance_threshold:** 0.95 — хороший баланс між інформативністю та простотою
2. **correlation_threshold:** 0.93 — достатньо високий для надійності
3. **overhead:** 0.1–0.2 — залежить від рівня шуму в даних

### Моніторинг інваріантів
1. **Періодичне переобучення:** Оновлювати інваріанти раз на тиждень/місяць
2. **Валідація:** Перевіряти, чи інваріанти все ще актуальні
3. **Логування:** Зберігати історію порушень для аналізу
