## Методологічний контекст

### Проблема: "Чому інваріант порушено?"

Виявлення інваріантів (Семінар 1) відповідає на питання **"Що не так?"**:
- ✅ Інваріант між CPU та температурою порушено
- ✅ Residual перевищує поріг на 15%

Але це не відповідає на питання **"Чому це сталося?"**:
- ❌ Яка саме метрика спричинила порушення?
- ❌ Чи це CPU, чи температура, чи обидві?
- ❌ Як розподілити "провину" між різними факторами?

### Концепція адитивного пояснення

**Ідея:** Розкласти відхилення від інваріанта на внески окремих ознак.

Якщо інваріант передбачає:
$$z_y^{\text{pred}} = a \cdot z_x + b$$

А фактичне значення:
$$z_y^{\text{actual}} = z_y^{\text{pred}} + \Delta$$

То:
$$\Delta = z_y^{\text{actual}} - z_y^{\text{pred}} = \sum_{i=1}^{d} \phi_i$$

де $\phi_i$ — внесок $i$-ї ознаки в відхилення.

## Математична формалізація SHAP

### Теорія ігор та значення Шеплі

**Значення Шеплі (Shapley Value)** — концепція з теорії кооперативних ігор, що розподіляє "виграш" між гравцями справедливим чином.

**Аналогія:**
- **Гравці** = ознаки (features) $x_1, x_2, \ldots, x_d$
- **Виграш** = відхилення від інваріанта $\Delta$
- **Задача:** Як розподілити $\Delta$ між ознаками?

### Формальне визначення

Для функції $f: \mathbb{R}^d \to \mathbb{R}$ та спостереження $\mathbf{x} = (x_1, \ldots, x_d)$, значення Шеплі для ознаки $i$:

$$\phi_i(f, \mathbf{x}) = \sum_{S \subseteq \{1,\ldots,d\} \setminus \{i\}} \frac{|S|!(d-|S|-1)!}{d!} \left[ f(S \cup \{i\}) - f(S) \right]$$

де:
- $S$ — підмножина ознак (коаліція)
- $f(S)$ — прогноз моделі з використанням лише ознак з $S$
- $f(S \cup \{i\})$ — прогноз з додаванням ознаки $i$

### Властивості значень Шеплі

#### 1. Ефективність (Efficiency)
Сума всіх значень Шеплі дорівнює різниці між прогнозом для поточного спостереження та базовим значенням:

$$\sum_{i=1}^{d} \phi_i = f(\mathbf{x}) - f(\emptyset)$$

де $f(\emptyset)$ — базове значення (середнє на фонових даних).

#### 2. Симетричність (Symmetry)
Якщо дві ознаки мають однаковий внесок у всіх коаліціях, їх значення Шеплі рівні.

#### 3. Нульовий внесок (Dummy)
Якщо ознака не впливає на прогноз, її значення Шеплі дорівнює нулю.

#### 4. Адитивність (Additivity)
Для комбінації моделей значення Шеплі адитивні.

## KernelSHAP: Апроксимація через зважену лінійну регресію

### Проблема обчислювальної складності

Точне обчислення значень Шеплі вимагає оцінки $f(S)$ для всіх $2^d$ підмножин ознак — експоненційна складність.

**Рішення:** KernelSHAP апроксимує значення Шеплі через зважену лінійну регресію.

### Алгоритм KernelSHAP

#### Крок 1: Генерація зразків

Для спостереження $\mathbf{x}$ та фонового набору $\{\mathbf{z}_1, \ldots, \mathbf{z}_m\}$:

1. Генеруємо $N$ випадкових бінарних векторів $\mathbf{z}'_j \in \{0,1\}^d$ (маски ознак)
2. Для кожної маски $\mathbf{z}'_j$ створюємо гібридний зразок:
   $$\mathbf{x}'_j = \mathbf{z}'_j \odot \mathbf{x} + (1 - \mathbf{z}'_j) \odot \mathbf{z}_k$$
   
   де $\odot$ — поелементне множення, $\mathbf{z}_k$ — випадковий зразок з фонового набору.

#### Крок 2: Обчислення ваг

Ваги для зразків визначаються через **Shapley kernel**:

$$w(\mathbf{z}') = \frac{(d-1)}{\binom{d}{\lvert\mathbf{z}'\rvert} \cdot \lvert\mathbf{z}'\rvert \cdot (d - \lvert\mathbf{z}'\rvert)}$$

де $\lvert\mathbf{z}'\rvert$ — кількість одиниць у маски.

#### Крок 3: Зважена лінійна регресія

Шукаємо коефіцієнти $\beta_0, \beta_1, \ldots, \beta_d$ мінімізуючи:

$$\sum_{j=1}^{N} w(\mathbf{z}'_j) \left[ f(\mathbf{x}'_j) - \left( \beta_0 + \sum_{i=1}^{d} \beta_i \cdot z'_{j,i} \right) \right]^2$$

Тоді:
- $\phi_0 = \beta_0$ — базове значення
- $\phi_i = \beta_i$ — значення Шеплі для ознаки $i$

## LIME: Локальна інтерпретована модель

### Концепція локальної апроксимації

**LIME (Local Interpretable Model-agnostic Explanations)** будує просту інтерпретовану модель *локально* навколо точки інтересу.

**Ідея:** Складну модель $f$ апроксимуємо простою моделлю $g$ в околі спостереження $\mathbf{x}$.

### Математична формалізація

#### Задача оптимізації

$$\xi(\mathbf{x}) = \arg\min_{g \in \mathcal{G}} \mathcal{L}(f, g, \pi_{\mathbf{x}}) + \Omega(g)$$

де:
- $\mathcal{G}$ — клас інтерпретованих моделей (наприклад, лінійні)
- $\mathcal{L}$ — функція втрат (наприклад, MSE)
- $\pi_{\mathbf{x}}$ — функція близькості (ваги зразків)
- $\Omega(g)$ — регуляризація (складність моделі)

#### Функція близькості

Для числових ознак використовуємо експоненційне ядро:

$$\pi_{\mathbf{x}}(\mathbf{z}) = \exp\left(-\frac{D(\mathbf{x}, \mathbf{z})^2}{\sigma^2}\right)$$

де $D(\mathbf{x}, \mathbf{z})$ — відстань між спостереженнями, $\sigma$ — параметр ширини ядра.

#### Алгоритм LIME для табличних даних

```
АЛГОРИТМ: LIME для регресії

ВХІД:
  - f: складна модель (black box)
  - x: спостереження для пояснення
  - X_background: фонові дані
  - N: кількість зразків (1000)
  - σ: ширина ядра (0.75)

ВИХІД:
  - g: локальна лінійна модель

1. ГЕНЕРАЦІЯ ЗРАЗКІВ:
   ДЛЯ i = 1 до N:
     a. z_i ← x + ε, де ε ~ N(0, σ²·I)
     b. y_i ← f(z_i)

2. ОБЧИСЛЕННЯ ВАГ:
   ДЛЯ i = 1 до N:
     w_i ← exp(-\|x - z_i\|² / σ²)

3. НАВЧАННЯ ЛОКАЛЬНОЇ МОДЕЛІ:
   g ← Ridge(α=0.1).fit(Z, Y, sample_weight=w)
   де Z = [z_1, ..., z_N], Y = [y_1, ..., y_N]

4. ПОВЕРНУТИ g
```

### Інтерпретація результатів LIME

Коефіцієнти локальної моделі $g(\mathbf{z}) = \beta_0 + \sum_{i=1}^{d} \beta_i z_i$ інтерпретуються як:

- $\beta_i > 0$: збільшення ознаки $i$ збільшує прогноз
- $\beta_i < 0$: збільшення ознаки $i$ зменшує прогноз
- $\lvert\beta_i\rvert$: важливість ознаки $i$

## Застосування до інваріантів

### Формалізація задачі

Нехай інваріант визначає залежність:
$$z_y = a \cdot z_x + b$$

де $z_x, z_y$ — PCA компоненти, отримані з ознак:
- $z_x = \text{PCA}_x(\mathbf{x}_x)$
- $z_y = \text{PCA}_y(\mathbf{x}_y)$

Для спостереження з порушенням:
- Фактичне: $z_y^{\text{actual}}$
- Прогнозоване: $z_y^{\text{pred}} = a \cdot z_x + b$
- Відхилення: $\Delta = z_y^{\text{actual}} - z_y^{\text{pred}}$

### SHAP для інваріантів

Функція-модель для SHAP:
$$f(\mathbf{x}) = \text{PCA}_y(\mathbf{x}_y)[\text{component\_idx}]$$

Тобто прогнозуємо фактичне значення $y$ компоненти на основі ознак.

**Властивість ефективності:**
$$\sum_{i=1}^{d} \phi_i = z_y^{\text{actual}} - \bar{z}_y$$

де $\bar{z}_y$ — середнє значення $y$ компоненти на фонових даних.

### LIME для інваріантів

Локальна модель навколо точки порушення:
$$g(\mathbf{x}) = \beta_0 + \sum_{i=1}^{d} \beta_i x_i$$

де коефіцієнти $\beta_i$ показують локальний вплив кожної ознаки на $z_y$.

## Візуалізація: Waterfall plot

### Структура waterfall plot

Waterfall plot показує, як базове значення перетворюється на фактичне через додавання внесків ознак:

```
Base Value
  + φ₁ (feature_1)
  + φ₂ (feature_2)
  ...
  + φₙ (feature_n)
= Actual Value
```

### Математична формалізація

Для впорядкованих за важливістю ознак:

$$v_0 = \text{base\_value}$$
$$v_i = v_{i-1} + \phi_{\sigma(i)} \quad \text{для } i = 1, \ldots, d$$

де $\sigma$ — перестановка індексів за спаданням $\lvert\phi_i\rvert$.

## Порівняння SHAP та LIME

| Критерій | SHAP | LIME |
|----------|------|------|
| **Теоретична основа** | Теорія ігор (Shapley Values) | Локальна апроксимація |
| **Властивості** | Ефективність, симетричність, адитивність | Гнучкість, локальність |
| **Обчислювальна складність** | O(N·d) для KernelSHAP | O(N·d) |
| **Інтерпретація** | Глобальна + локальна | Локальна |
| **Стабільність** | Висока (унікальні значення) | Залежить від зразків |
| **Застосування** | Адитивне пояснення внесків | Швидка інтерпретація окремих сплесків |

### Коли використовувати SHAP?

- ✅ Потрібна теоретично обґрунтована розподіл "провини"
- ✅ Важлива властивість ефективності (сума = різниця)
- ✅ Потрібна стабільність результатів

### Коли використовувати LIME?

- ✅ Швидка інтерпретація окремих аномалій
- ✅ Потрібна простота (лінійна модель)
- ✅ Гнучкість у виборі типу моделі

## Обмеження та обережності

### SHAP

1. **Обчислювальна складність:** Для великих моделей може бути повільним
2. **Залежність від фонового набору:** Результати залежать від вибору background data
3. **Припущення про незалежність:** Може не враховувати кореляції між ознаками

### LIME

1. **Нестабільність:** Різні запуски можуть давати різні результати
2. **Локальність:** Пояснення дійсні лише в околі точки
3. **Вибір параметрів:** Ширина ядра $\sigma$ впливає на результати

---

## Обмеження: Кореляція vs Причинність

### Важливе застереження

**SHAP та LIME показують кореляції, а не причинність.**

Це означає, що високий внесок ознаки в порушення інваріанта не гарантує, що зміна цієї ознаки виправить проблему.

**Приклад:**

```python
# SHAP каже: "cpu_usage додав +200ms до latency"
# Але чи cpu_usage ВИКЛИКАЄ latency?

# Можливі сценарії:
# 1. Causal: cpu_usage → latency (зменшення CPU справді допоможе)
# 2. Confounding: user_count → cpu_usage, user_count → latency
#    (зменшення CPU не допоможе, бо спільна причина — user_count)
# 3. Reverse causation: latency → cpu_usage (висока latency викликає високе CPU)
```

### Проблема плутанини (Confounding)

**Плутанина** — це ситуація, коли дві змінні корелюють не через причинний зв'язок, а через третю змінну (confounder).

```
Confounder (кількість користувачів)
    ↓              ↓
cpu_usage      latency
```

SHAP може показати високий внесок `cpu_usage`, але насправді обидві змінні залежать від `user_count`.

### Що це означає для діагностики?

1. **SHAP/LIME — це початок, а не кінець.** Вони показують, які ознаки корелюють з проблемою, але не гарантують причинно-наслідковий зв'язок.

2. **Для критичних рішень потрібен Causal Inference.** Якщо ви плануєте змінити конфігурацію на основі SHAP результатів, перевірте причинність через Causal Inference (див. [Блок 6](./06_future_causal_inference.md)).

3. **Causal-Aware оцінка контрфактуалів.** У [Семінарі 3](./09_seminar3_performance_doctor.md) ми інтегруємо causal awareness для перевірки, чи дійсно рекомендації спрацюють.

## Висновок

SHAP та LIME надають потужні інструменти для пояснення порушень інваріантів. SHAP забезпечує теоретично обґрунтований розподіл внесків, тоді як LIME надає швидку локальну інтерпретацію.

**Наступний крок:** Коли ми зрозуміли *чому* інваріант порушено, потрібно знайти *що змінити*. Це завдання вирішує [Семінар 3: Контрфактуальна терапія](./09_seminar3_performance_doctor.md).
