# Науково-дослідна специфікація (Постановка задачі)
## Тема: Урбаністичне масштабування мікросервісних IT-систем: перевірка гіпотез сублінійної економії та суперлінійної деградації

---

### 1. Вступ та актуальність дослідження
Сучасні великі програмні комплекси (Service Mesh, хмарні мікросервісні архітектури Netflix, Uber, Amazon) еволюціонують від простих статичних систем до складних динамічних екосистем, що налічують тисячі автономних вузлів. Традиційні підходи до оцінки їхньої продуктивності та надійності базуються на лінійних моделях або класичній теорії масового обслуговування, які часто ігнорують ефекти мережевої взаємодії та системної поведінки.

У фізиці складних систем та соціології встановлено, що міста функціонують не як лінійні структури, а як живі організми, що підпорядковуються законам алометричного масштабування (непропорційної зміни властивостей при зміні розмірів). Зокрема:
*   **Інфраструктура міст** (дороги, лінії електропередач, заправні станції) масштабується **сублінійно** (коефіцієнт $\beta \approx 0.85$), забезпечуючи суттєву економію ресурсів на масштабі.
*   **Соціоекономічні проблеми** (злочинність, поширення хвороб) масштабуються **суперлінійно** ($\beta \approx 1.15$), тобто зростають швидше, ніж населення.

**Наукова аналогія:** Мікросервісна архітектура — це цифровий мегаполіс. Окремі мікросервіси є "мешканцями" міста, шини повідомлень та API-шлюзи — "дорожньою мережею", а системні збої, витоки пам'яті, затримки та кібератаки — "цифровою злочинністю" (digital crime). Дане дослідження спрямоване на математичне підтвердження та вимірювання цих ефектів у великих програмних системах.

---

### 2. Об'єкт, предмет та мета дослідження

*   **Об'єкт дослідження:** Процес горизонтального та вертикального масштабування розподілених мікросервісних систем (на базі Kubernetes, Docker, Istio Service Mesh).
*   **Предмет дослідження:** Математичні закономірності зміни обсягів споживання спільних інфраструктурних ресурсів та частоти виникнення каскадних відмов і вразливостей безпеки як функцій від розміру системи.
*   **Мета роботи:** Побудувати та експериментально верифікувати математичну модель алометричного масштабування мікросервісних систем для оптимізації їхнього сублінійного ресурсоспоживання та запобігання суперлінійній деградації надійності й безпеки.

### 3. Наукові гіпотези для перевірки

Студент у своїй роботі має математично та експериментально підтвердити або спростувати наступну систему гіпотез:

#### Гіпотеза 1 (Сублінійне масштабування цифрової інфраструктури)
Обсяг спільно використовуваних ресурсів $I$ (наприклад, загальний об'єм CPU/RAM бази даних, завантаження брокера повідомлень Kafka, затримка комутації мережі шлюзу) при збільшенні кількості активних мікросервісів $N$ масштабується за сублінійним степеневим законом:
$$I(N) = I_0 \cdot N^{\beta_{infra}}, \quad \text{де } \beta_{infra} < 1 \text{ (орієнтовно } 0.80 - 0.88\text{)}$$
*Фізичний зміст:* Подвоєння кількості мікросервісів у системі повинно вимагати менше ніж подвоєння потужності центральних баз даних завдяки оптимізації спільних каналів зв'язку та ефекту агрегації запитів.

#### Гіпотеза 2 (Суперлінійне масштабування системних збоїв та вразливостей)
Кількість каскадних відмов, уразливостей безпеки, помилок маршрутизації та запізнень обробки запитів (p99 latency) $F$ при збільшенні розміру системи $N$ масштабується суперлінійно:
$$F(N) = F_0 \cdot N^{\beta_{failure}}, \quad \text{де } \beta_{failure} > 1 \text{ (орієнтовно } 1.12 - 1.20\text{)}$$
*Фізичний зміст:* Зі зростанням складності системи кількість можливих парних зв'язків та крос-компонентних взаємодій зростає нелінійно, що породжує "цифрову злочинність" (наприклад, уразливості конфігурацій) та каскадні аварії, які поширюються лавиноподібно.

### 4. Математичний апарат та методологія

Для реалізації дослідження студент повинен застосувати такі математичні методи:

1.  **Степеневі закони (Power Laws):** Моделювання залежності $Y = Y_0 N^\beta$.
2.  **Метод найменших квадратів у логарифмічних координатах:** Для знаходження показника масштабування $\beta$ шляхом лінеаризації даних:
    $$\ln(Y) = \ln(Y_0) + \beta \ln(N)$$
    Кут нахилу лінії регресії безпосередньо визначає коефіцієнт масштабування $\beta$.
3.  **Теорія фрактальних мереж (WBE-модель):** Аналіз ефективності топології зв'язків між сервісами як самоподібних розгалужених графів.
4.  **Аналіз важкохвостих розподілів (Heavy-tailed distributions):** Використання розподілу Парето для опису затримок (latency) та аномальних навантажень.

### 5. План виконання експериментальної частини

Для збору даних та верифікації моделей студенту пропонується такий прикладний стек та послідовність дій:

```
  [ Тестовий стенд: Kubernetes ]
                 │
                 ▼
  [ Генератор навантаження (Locust/k6) ] ──► (Масштабування N сервісів: 10 -> 50 -> 100 -> 500)
                 │
                 ▼
  [ Збір метрик (Prometheus/Jaeger APM) ]
                 │
                 ▼
  [ Обробка даних (Python/Pandas/Scipy) ] ──► (Побудова Log-Log регресії, визначення Beta)
```

1.  **Розгортання мікросервісного стенду:** Створення синтетичного мікросервісного додатку (наприклад, копія інтернет-магазину Google Cloud Microservices Demo).
2.  **Масштабування вузлів ($N$):** Ітераційне збільшення кількості мікросервісів від $N_1 = 10$ до $N_k = 500$.
3.  **Емуляція "злочинності" та збоїв:**
    *   Впровадження хаос-інжинірингу (Chaos Engineering за допомогою Chaos Mesh або LitmusChaos) для симуляції випадкових відмов мережі.
    *   Сканування вразливостей конфігурацій (Trivy, Kubescape) на кожному етапі масштабування.
4.  **Збір телеметрії:** Фіксація утилізації ресурсів (CPU, RAM, I/O) та метрик помилок/затримок за допомогою Prometheus та Grafana.
5.  **Статистичний аналіз:** Побудова лог-логарифмічних регресій, визначення точних значень $\beta_{infra}$ та $\beta_{failure}$, оцінка статистичної значущості відхилень.

### 6. Очікувані наукові та практичні результати

*   **Для теорії:** Створення єдиної концептуальної моделі "IT-система як цифрове місто", що розширює межі застосування алометричного аналізу на штучні складні системи.
*   **Для практики:** Розробка алгоритму **Perspective Maintenance** (перспективного самозагоєння) для оркестраторів (на кшталт Kubernetes). Алгоритм на основі поточних коефіцієнтів $\beta$ системи прийматиме рішення: коли масштабування є вигідним, а коли воно веде до катастрофічного зростання ризиків (насичення $\beta_{failure}$), і як переналаштувати топологію зв'язків для мінімізації накладних витрат.
