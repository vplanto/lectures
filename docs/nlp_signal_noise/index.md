# Курс: NLP у Технічних Доменах: Від Теореми Байєса до AI-SRE
## Тема: Пошук Сигналу в Шумі (The Signal in the Noise)

**Автор:** Віталій Платонов
**Аудиторія:** Студенти 2-3 курсу (Прикладна математика, CS)

---

### Анотація
Чому інженери ігнорують 99% сповіщень системи моніторингу? Курс розглядає фундаментальну проблему "пошуку голки в копиці сіна" через призму теорії ймовірностей та сучасного NLP. Ми пройдемо шлях від класичної формули Байєса (18 століття) до трансформерів BERT (21 століття), щоб створити "розумний фільтр" для технічних логів.

---

### Структура курсу (Навігація)

#### Блок 1: Інтуїція та Математична Пастка
Вступ через парадокс, який пояснює, чому інтуїція підводить нас при оцінюванні рідкісних подій (помилок, хвороб, атак).

* **[00_the_bayesian_trap.md](./00_the_bayesian_trap.md)**
    * **Тема:** Пастка Байєса (Recap відео Veritasium).
    * **Зміст:** Розбір прикладу з медичним тестом. Поняття `False Positive` vs `False Negative`. Чому тест з точністю 99% помиляється в 90% випадків, якщо хвороба рідкісна. Формула повної ймовірності.
    * **Матеріали:** Відео Veritasium, базовий Python скрипт для симуляції парадоксу.

* **[01_noise_in_production.md](./01_noise_in_production.md)**
    * **Тема:** Проблематика індустрії: Логи, Спам, Фрод.
    * **Зміст:** Мапінг медичної задачі на IT. "Хвороба" = "Критичний збій бази даних" (трапляється рідко). "Симптом" = "Рядок Error у логах" (трапляється часто). Чому `grep "Error"` не працює. Поняття "Base Rate Fallacy" в DevOps (Alert Fatigue).

#### Блок 2: Статистичний Підхід (Frequency-based)
Класичні методи, які працюють з частотою слів (Bag of Words).

* **[02_math_setup_classification.md](./02_math_setup_classification.md)**
    * **Тема:** Математична формалізація задачі класифікації.
    * **Зміст:** Текст як множина токенів $X = \{w_1, w_2, ... w_n\}$. Постановка задачі $P(Class | Features)$. Теорема Байєса: $P(Spam|Word) = \frac{P(Word|Spam)P(Spam)}{P(Word)}$.
    
* **[03_naive_bayes_deep_dive.md](./03_naive_bayes_deep_dive.md)**
    * **Тема:** "Наївний" Байєс та його межі.
    * **Зміст:** Чому він "наївний" (припущення незалежності слів). Чому це працює для спаму (слова "віагра" і "казино" корелюють), але погано для логів ("Connection" і "Refused" важливі тільки разом). 

#### Блок 3: Геометричний Підхід (Semantic-based)
Перехід від "підрахунку слів" до "розуміння змісту". Використання векторної алгебри.

* **[04_geometry_of_meaning.md](./04_geometry_of_meaning.md)**
    * **Тема:** Від слів до векторів (Embeddings).
    * **Зміст:** Проблема синонімів ("DB down" vs "Connection lost"). Векторні простори ($R^N$). Косинусна відстань як міра схожості. Word2Vec інтуїція: $King - Man + Woman = Queen$.

* **[05_bert_and_transformers.md](./05_bert_and_transformers.md)**
    * **Тема:** Трансформери в технічному аналізі.
    * **Зміст:** Архітектура BERT (Bidirectional Encoder Representations). Механізм Self-Attention: як модель розуміє контекст. Чому BERT краще бачить аномалії в послідовності подій, ніж Байєс. Використання `[CLS]` токена для класифікації інцидентів.

#### Блок 4: Практикум (Workshop)
Створення працюючого прототипу.

* **[06_synthetic_chaos_generator.md](./06_synthetic_chaos_generator.md)**
    * **Тема:** Генерація синтетичного датасету.
    * **Зміст:** Проблема конфіденційності реальних логів. Як згенерувати "правильний шум" та "рідкісні аномалії" за допомогою Python (бібліотека `Faker` або промптинг LLM). Створення незбалансованого датасету (99% ОК, 1% Error) для перевірки Пастки Байєса.

* **[07_implementation_workshop.md](./07_implementation_workshop.md)**
    * **Тема:** Побудова пайплайну фільтрації.
    * **Зміст:** Live-coding сесія.
        1. **Baseline:** Реалізація Naive Bayes (scikit-learn) — отримання високої точності, але низького Recall (пропуск аномалій).
        2. **Advanced:** Реалізація BERT-based classifier (HuggingFace) — покращення детекції контекстних помилок.
        3. **Metric War:** Порівняння Accuracy vs F1-score на незбалансованих даних.

* **[08_course_summary.md](./08_course_summary.md)**
    * **Тема:** Підсумки та майбутнє (LLM Agents).
    * **Зміст:** Що ми вивчили. Куди рухатись далі: RAG (Retrieval-Augmented Generation) — щоб AI не просто класифікував помилку, а й писав інструкцію з її виправлення (Runbook Automation).

#### Семінари: Заповнення Прогалин Між Теорією та Практикою
Додаткові практичні модулі для глибшого розуміння концепцій.

* **[09_seminar_high_dimensional_geometry.md](./09_seminar_high_dimensional_geometry.md)**
    * **Тема:** Геометрія високих розмірностей та візуалізація.
    * **Зміст:** Чому це важливо: BERT вектори мають 768 розмірностей. Студентам важко уявити таку "геометрію значень". Розгляд методів зниження розмірності (t-SNE, UMAP). Практика: Візуалізація того, як вектори логів "збиваються" у кластери за типами інцидентів (наприклад, окремий кластер для Database errors, окремий для Network timeouts).

* **[10_seminar_metrics_extreme_imbalance.md](./10_seminar_metrics_extreme_imbalance.md)**
    * **Тема:** Метрики в умовах екстремального дисбалансу класів.
    * **Зміст:** Чому це важливо: Джерела зазначають, що Accuracy оманлива на незбалансованих даних. Поглиблений розбір Precision-Recall Curves (PRC) порівняно з ROC-AUC. Чому PRC є більш інформативною для рідкісних подій (Base Rate < 0.1%). Математика: Виведення взаємозв'язку між Base Rate та Precision через теорему Байєса.

* **[11_seminar_efficient_nlp_quantization_distillation.md](./11_seminar_efficient_nlp_quantization_distillation.md)**
    * **Тема:** Ефективний NLP: Квантизація та Дистиляція.
    * **Зміст:** Чому це важливо: BERT — велика і дорога модель (110M+ параметрів), що створює проблеми для моніторингу в реальному часі. Знайомство з DistilBERT та методами зменшення розміру моделей без значної втрати якості. Практика: Порівняння швидкості обробки логів (inference time) базовим BERT та оптимізованою моделлю.

* **[12_seminar_regex_vs_tokenizers.md](./12_seminar_regex_vs_tokenizers.md)**
    * **Тема:** Регулярні вирази vs Токенізатори.
    * **Зміст:** Чому це важливо: Перш ніж текст стане вектором, його треба очистити. Технічні логи "брудні" (IP-адреси, хеші). Семінар з ефективного парсингу логів та створення кастомних токенізаторів, які не розбивають важливі технічні сутності (наприклад, java.lang.NullPointerException має сприйматися як один токен).
